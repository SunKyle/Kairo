## 1. 问题的形状

模型不能产出情绪，也不能产出图片字节 —— 它只能产出**意图**。Kairo 现在的做法是把意图做成一枚写在回复里的 `[kind:payload]` 标签，服务端负责把它剪下来。

眼下的剪取层是**按位置切**的三条路：`splitTags` 管末尾、`stripStandaloneTags` 管"顶在行首、独占一行"、`tailHold` 管流式期间扣尾。这套设计对只有 `photo` + `mood` 两枚标签来说是稳的 —— 但**每加一枚 kind、每冒一种新的位置变体，都要在三处各补一刀**，且三处的判据必须严格同步，否则漏一条就原样上屏。

具体三个信号告诉你这套结构到顶了：

1. **`isTagRoom` 那个增量前缀状态机已经写死了两个 kind 的全前缀叉积**（[chatTags.js](../server/chatTags.js) 的 `isTagRoom`）：`p|h|ho|hot|photo | m|o|oo|ood`。加 `music` 和 `video` 就变成 `p|m|mu|mus|music|v|vi|vid|vide|video` 十个 token 的枚举，同一行正则膨胀到不可读，还要与 `PHOTO_PARTIAL_RE` / `MOOD_PARTIAL_RE` / `head0` 三处**同步**。任何一处漏改，边界就漏。
2. **今天这条 bug（`[photo:…]这回…`）本质上是"三条路的位置白名单没能覆盖第四种位置"**。窄修复（顶到行首也认）只是把白名单再加一格；同类的第五、第六种（`正文 [photo:…] 正文`、`[photo:` 里出现方括号或换行 …）现在仍然会漏。
3. **`music` / `video` 一旦上线，同一个走形会被撞到 4 倍**。因为它们共用同一条 prompt 纪律（"写在末尾"），模型不遵守的方式也一样多。

## 2. 判据从「位置」换到「形状」

通用方案只有一句话：**不看这枚标签在文本的哪个位置，只看它自己是不是长成了一枚合法标签**。

位置本来就是"像不像标签"的一个代理信号，代价是它把所有"不像末尾 / 不像整行"的真标签一起挡掉了。用名字 + 形状做判据，位置这个维度**直接不需要**——`splitTags` 与 `stripStandaloneTags` 合并成一个纯函数 `extractTags`，`tailHold` 里那套"从末尾往回剥"的复杂度直接蒸发。

## 3. 注册表：`TAGS`

> **注意**：本节与 §4 / §5 描述的是**收益②（形状判据）**的注册表形状，**未实现**。收益①已落地的注册表是同一个 `TAGS` 数组，但每项字段是 `trailingRe / partialRe / parse / fields / empty` —— 仍按位置剪，只是把 kind 名字收进了一处。下面这个 `parseShape / maxInner` 版本留给未来做②时参考。

一层新的心智：**kind 是注册出来的，不是散落出来的**。

```ts
// server/tags.js（改造后的模块命名）
type TagDef = {
  name: 'photo' | 'mood' | 'music' | 'video' | string
  /** 形状判据：内层字符集 + 长度 + 可选的语义校验。返回归一化后的意图 payload，
   *  校验不过返回 null —— 那一刻这串 `[name:…]` 就被当成正文留下 */
  parseShape(inner: string, ctx: { charName: string }): unknown | null
  /** 流式扣尾用：这一 kind 最长可能占多少字符。用它算 OPEN_TAIL 的窗口 */
  maxInner: number
}

export const TAGS: TagDef[] = [
  { name: 'photo', parseShape: parsePhotoShape, maxInner: 400 },
  { name: 'mood',  parseShape: parseMoodShape,  maxInner: 20  },
  { name: 'music', parseShape: parseMusicShape, maxInner: 200 },
  { name: 'video', parseShape: parseVideoShape, maxInner: 200 }
]
```

**形状分级是通用化独有的红利**（位置方案里三条路共用一条判据，无法按 kind 收严）。每 kind 独立定义碰撞面：

| kind | 形状 | 误伤风险 | 缓解 |
| --- | --- | --- | --- |
| mood | `/^[a-z][a-z-]{1,19}$/`（枚举） | 最低 | 无 |
| photo | 自由文本 1..400、不含方括号 | 低 | 位置方案原本也不吃 `正文 [photo:x]`；通用方案里 `[photo:x]` 只要**整枚自包含**就吃 —— 加一条"内层必须含逗号/冒号/`:` 前缀"这类弱语义可再收紧 |
| music | 建议 `名称 [–—-] 艺人?`，含 `:` 或 ` - ` 才算 | 低 | 语义前缀要求；或走 `id:` / `title:` 双段结构 |
| video | 建议 URL / 平台 ID 形状 | 最低 | 强形状判据 |

**加一枚新 kind 时，同时提交它的 parseShape 与至少 3 条误伤护栏用例**（"角色在正文里讨论这个协议本身"、"用户引用了别的系统里 `[video:…]` 记号"、代码块里的字面串），否则不给通过。

## 4. 单遍 `extractTags`

```
function extractTags(text, ctx):
  out = ""        // 剪干净之后的正文
  cursor = 0
  intents = {}    // 每 kind 各记一份，同 kind 多枚时 last-wins（对齐现有 flushTail 里"末尾优先"）
  while cursor < text.length:
    idx = findNextOpenBracket(text, cursor)
    if idx < 0: out += text.slice(cursor); break
    nameMatch = matchTagName(text, idx + 1)      // 从 TAGS 里比对最长 name 前缀
    if not nameMatch: out += text.slice(cursor, idx + 1); cursor = idx + 1; continue
    sepMatch = /^\s*[:=]/.exec(...)
    if not sepMatch: ...同上，当正文
    close = findCloseBracket(text, after sepMatch)
    if close < 0:  // 到文本末尾都没闭合 → 流式扣尾用得上，不剪、原样留给下一段
      out += text.slice(cursor, idx); cursor = idx; break
    inner = text.slice(after sepMatch, close)
    parsed = TAGS[name].parseShape(inner, ctx)
    if parsed == null:  // 形状不对 → 整枚当正文留下
      out += text.slice(cursor, close + 1); cursor = close + 1; continue
    intents[name] = parsed    // last-wins
    cursor = close + 1
  return { text: normalizeWhitespace(out), ...intents }
```

关键几个纪律：

- **last-wins 与现有一致**。当前 `flushTail` 就是"末尾那枚赢中段"（[chat.js](../server/routes/chat.js) 的 `flushTail`），改成通用扫描后自然等价。
- **normalizeWhitespace**：剪掉标签后前后各留一份空白，压成一处；行首标签 + 尾随正文 → 只留尾随正文那一行；独占一行的标签 → 整行连换行一起吞。**这一条要把现在 stripStandaloneTags 里"空行收一收"那段行为搬过来**，别丢。
- **不检查内层换行**（沿用当前 `completeTagStart` 的纪律：场景描述本身就长、会带换行，任何"含换行就不是标签"的规则都会把合法标签判掉）。**但要检查内层方括号**——含 `[` 或 `]` 直接判形状不过。
- **形状不过 = 整枚留回正文**，与今天 splitTags 里"半截只擦不取"是同一层思路；只是"半截"的判据从"到末尾了没闭合"变成"这整段都不像一枚标签"。

## 5. `tailHold` 怎么塌一半

现在 130 行里的 `completeTagStart` + `isTagRoom` + `head0`（三处判据协同、右往左逐段剥）都是为了一件事——**别把末尾的标签放出去**。改成"通用扫描 + 形状判据"之后：

- **放出去也没关系**：只要它是完整标签、形状对，`extractTags` 会当场剪掉；形状不对（`[1]`、`[注]`）就照原样上屏，那本来就该是正文。
- **唯一真正要扣住的**：**没闭合的那一截尾巴**（`[photo:self:me on the bal`）。因为这一刻我们还不知道它是"完整标签"还是"半截的正文"。

于是 `tailHold` 缩成一条：**从最后一个未闭合的 `[` 的位置往前都放，往后整段扣**。伪码：

```
function tailHold(buffer):
  for i from buffer.length-1 down to 0:
    if buffer[i] == '\n': return buffer.length   // 换行之前不可能有未闭合标签跨行
    if buffer[i] == ']':  return buffer.length   // 已经闭合了 —— 交给 extractTags 处理
    if buffer[i] == '[':
      // 只在"这个 [ 可能是某 kind 的开头"时才扣住；否则它是散句里的 [，照放
      if couldStartAnyTagName(buffer, i+1): return i
      else: continue
  return buffer.length
```

`couldStartAnyTagName(buffer, k)` 从 `TAGS` 里所有 name 逐个查前缀 —— 现在的枚举式 `p|h|ho|hot|photo|m|o|oo|ood` 状态机由这个函数**从注册表派生**出来，加 kind 不用手改。

**相邻两枚标签的老坑**（[chatTags.js](../server/chatTags.js) 里"探针抓到过"那两条注释）在这版里怎么解？——不再需要解，因为它本来就是"位置判据"派生出来的问题。形状判据下：`[photo:x]\n[m` 里 `[m` 未闭合 → 扣住；`[photo:x]` 已闭合 → 释放，`extractTags` 走一遍就剪干净。
