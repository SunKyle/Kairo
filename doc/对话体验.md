## 0. 定位：同一页的第二种骨架 + 三层表达

对话体验由两半组成，它们落在同一个页面上：

| 半 | 回答的问题 | 本文位置 |
|---|---|---|
| **沉浸**（骨架 + 机制） | 怎么让用户忘了自己在用一个软件 | §1–§5、§7 |
| **分层**（说 / 想 / 做） | 一轮话该以几种语域出现 | §6 |

两半各有一句定位：沉浸式对话是对话页的**第二种骨架**，不是第二个页面 —— 把工具那一层收走，把画面还给角色；说 / 想 / 做不是三种排版，是三种**信息归属规则** —— 谁能看见、会不会进入角色之后的记忆，规则定死，视觉自然落下来。

> 判据沿用[设计系统.md](设计系统.md)：**让能力隐藏，让过程自然。**

## 1. 沉浸感是什么

> **沉浸感 = 用户不再意识到「界面」这一层的存在。**
> 换个说法：沉浸感 ≈ 破功次数 ≈ 0。

这条定义立刻给出方法论：

- **先减法**：逐条堵住「出戏」的瞬间。破功是可以数出来的，氛围不可以。做减法可验收。
- **后加法**：供给「它是活的」的证据。只堵不漏的对话是「干净的应答机」，不是人。
- **都不做**：表演式的拟人化（贴纸、假状态、假在线）。一旦被识破，之前所有的「它在」都一起作废。

三条判据：① 用户关掉页面十分钟后复述这段对话，说的是「它说了什么」，而不是「我点了什么」；② 用户记不住刚才有没有等过 —— Loading 留下的印象越淡越好；③ 用户会主动回来，而不是被通知叫回来。第三条是分水岭：被通知叫回来的是工具，主动回来的是关系。

### 1.1 三根支柱

| 支柱 | 用户心里在问 | 靠什么供给 | 破功长什么样 |
|---|---|---|---|
| **连续性** | 它还记得我吗？还是同一个人吗？ | 记忆、时间、人格一贯 | 复读机、失忆、你刚才不是这么说的 |
| **在场感** | 它现在在这儿吗？ | 流式、打字节奏、情绪、声音、图 | 转圈、等 5 秒憋出一整段、面无表情 |
| **能动性** | 它是个人，还是个应答机？ | 拒绝、边界、有自己的事、会主动 | 每轮反问、还有什么可以帮你的、有求必应 |

> 还有第四个候选：**语境**（你们俩现在在哪儿、什么时候说话）。它不单独立柱 ——「什么时候」属于连续性，「在哪儿」属于在场感，分开会让这份文档多一栏而少一条可执行的东西。

这三条里，**连续性最省力、在场感最要紧、能动性最危险**：前两条做错了只是「不像」，第三条做错了（假装在线、假装忙）会**直接毁掉关系**。

## 3. 连续性

### 3.1 时间注入（已落地）

**落地（2026-10-20）：`timeContext` 已接进 `chatSystemPrompt`，前端算好 `nowLocal` 与 `lastAt` 传入。** 下面的设计判断保留作决策记录；当年写这段时 system 里确实没有任何时间信息 —— 角色不知道现在是凌晨两点、也不知道上次说话是三天前，而这两件事恰恰是真人在聊天里最先注意到的（「这么晚还没睡」）。

```
Right now: 2026-10-05 23:41, Sunday (the user's local clock, real world only — the story may be at another time).
You two last spoke 3 days ago.
```

| 决定 | 为什么 |
|---|---|
| **放在「What you remember」之前**，属「事实」那一层 | 它和记忆是同一类东西：「发生过什么、现在是什么时候」 |
| 由**前端算相对量**（「3 天前」），服务端只做拼装 | 时区在前端是对的，服务端不知道用户在哪儿；而且这与「人格字段由前端发结构、服务端拼提示词」是同一套分工 |
| **不要精确到秒** | 23:41:07 是机器的时间。分钟已经够了，而且不会随请求漂移 |
| 有新鲜感上限 | 超过约 30 天没说话就不报间隔（「两个月前」会让它开口就 uncomfortable）——退回只说当前时间 |
| 补一条规则：「只在真的相关时提」 | 否则它会**每轮**都说「现在是晚上」——比没有时间感更假 |
| **明确标注它只是「现实世界的钟」** | 剧情有自己的时间：现实里过了三分钟，剧情里可能过了三天。不划界，模型会拿现实时间推断剧情里的「现在」，把早已发生过的承诺重新当成待办 |
| 首次对话（无上一条）只给当前时间 | 开场白因此能自然（「这个点还没睡？」） |

### 3.2 记忆的锚点（永久钉住未做）

现在记忆是「旧记忆 + 新消息 → 重写一份」，所以用户手改过的措辞会在下一轮被润色掉 —— 这一条记为未解决风险。落法是 ChatSummary 加一个 `pinned?: boolean`（或一张极小的 `chat_facts` 表）：

- `pinned` 之后**不再把旧记忆喂回模型**，只让新消息往后接 —— 那段文字停止进化；界面上的差别只有一处：记忆块上多一枚「钉住」，改过之后自动点亮；
- 取舍要写清楚：**一旦钉住，它就永远是那句话**。这是「可信」与「会成长」的取舍，所以要**由用户按下去**，不能由我们替他决定；
- 顺带补一条**它自己该记住什么**的规则：名字、地点、承诺、欠下的账。这三样正是「三天后回来还追着你要」的东西 —— 记忆的取舍标准不是信息量，是**可追讨性**。

现状：已防「本轮中途被覆盖」，`pinned` 本身未做。

### 3.3 回到对话的续接（已落地）

**落点改过（2026-10-05，实现时才发现）。** 原稿写的是「空态里补一行」，但空态只在**一条消息都没有**时出现（`v-if="!msgs.length"`）—— 也就是说，恰恰在「有一段旧对话要接上」的时候它不出现。落点因此改成**消息流的末尾**：

```
      "……"
      "路上小心。"
  Last spoke 3 days ago        补这一行
```

| 决定 | 为什么 |
|---|---|
| 补在**末尾**，不在顶上 | 回来时眼睛落在最新那一条上，而顶部要往上翻才看得到 |
| **不引用最后一句** | 那一条就在它上面一格 —— 复述一遍是纯噪声 |
| 阈值沿用时间分隔那条（30 分钟），超过 30 天换「2 months ago」这一档粒度 | 刚聊完去别处转一圈回来不该看见它；而隔了半年还说 183 days ago 是机器在报数 |
| 措辞与**角色被告知的那句同源**（`agoLabel`，[chatTime.js](../server/chatTime.js)） | 同一个事实在界面与提示词里说成两样，用户会以为它们在讲两件事 |
| **纯本地派生，不调模型** | 一进页面就花钱不对 |
| 措辞是「Last spoke」而不是「History」 | 前者是关系，后者是数据库 |
| **不替角色说话** | 不要写成「它说：快回来」—— 那是伪造它的发言，属于反模式第一条 |

> **顺带发现（未修，记一笔）**：消息是异步从 IndexedDB 读的，而空态只看 `!msgs.length` —— 所以每次进入一个**聊过**的角色，都会有一瞬间的「Say something to X」。本地读通常快到看不见，所以它是一条**潜在**的闪烁；真要修得给「还没读完」一个与「真的没有」不同的状态。

### 3.4 遗忘要有叙事，买不起的那一半要认

`Forget memory` 之后角色是真的不记得了，这是对的。补一条纪律：**忘掉之后不要在提示词里安排它「想不起来」**（「我不记得你说过」）—— 那是在演失忆。让它**自然地不问、不接**就够了：真人忘了事，是不会主动宣布的。

另一半是反向的：记忆存在本地 IDB，换设备就没有。这一点不修，也不粉饰 —— 界面上如实说「它记得什么只存在这台设备上」，比让用户以为记忆丢了强（§2.D）。

## 4. 在场感

### 4.1 首字节预算要变成一个数字

流式是这一页**最重要的一步**（「等 5 秒憋出一整段，拟人感当场崩掉」）。但「用了流式」不等于「够快」：真正决定观感的是**首字节延迟（TTFB）**。建议把它当成一条产品指标看待：**P50 < 1.2s，P95 < 3s**，超出的部分才需要表现层补。在此之前不要用假的「正在输入…」去掩盖慢 —— 那会让慢变得可以忍受，于是没人去修。

**现状（2026-10-20）**：`useChatFlow` 里有 dev-only 的 `performance.measure('kimage-chat-ttfb')` + `console.debug`，不进产品、不落盘、不上报；尚无面板、预算与回归门。模型 / 网络一变，这个数字仍要靠开发者自己看控制台。

### 4.2 打字节奏器（已落地，客户端纯表现层）

**落地（2026-10-20）**：`Pacer` 已接进 `useChatFlow` 的 `onDelta` —— 只延后、不加速、总延迟封顶，`document.hidden` 时直接放行，Stop 时 `flush()` 冲刷。

原先这里是 `onDelta: (delta) => { reply.content += delta }` —— 增量到即渲染，所以**吐字速度 = 模型的吐字速度**，而模型是匀速的。**匀速正是「机器感」的来源**。

| 规则 | 实际值（[typing.ts](../src/lib/typing.ts)） |
|---|---|
| 句末标点（。！？!?…）之后 | 基准 150ms × 0.7–1.3 → 约 105–195ms |
| 逗号、顿号、分号、冒号之后 | 基准 80ms × 0.7–1.3 → 约 56–104ms |
| 换行 / 段落之前 | 基准 260ms × 0.7–1.3 → 约 182–338ms |
| 单次停顿上限 / 整条预算 | `MAX_PAUSE_MS = 400` / `PACE_BUDGET_MS = 1200` |
| 抖动的来源 | **用 msg.id + 位置做哈希**，不用 `Math.random()` |

| 决定 | 为什么 |
|---|---|
| **只延后，不加速，且总延迟封顶**（1.2s） | 目的是消除「匀速」，不是让人多等。超出预算就直接放行 |
| 哈希取抖动，不取随机 | 同一个 id 重播一致、可测；也让「重生成」能拿到另一条节奏 |
| 页面不可见（document.hidden）时**直接放行** | 没人在看的时候不该攒着 |
| 节奏器只活在**渲染层** | 落库的是完整正文 —— 重新进页面时不会重演一遍打字，那是鬼畜 |
| Stop 时**立即冲刷**剩余缓冲 | 按了停还慢慢吐字是惩罚用户 |

这条之所以值得单列：它是**唯一一条不改模型、不改提示词、不改成本就能去掉机器感**的改动。

### 4.3 连发气泡（已落地，但不带开关）

**落地（2026-10-20）**：`splitAssistantReply` 在渲染层按**空行段落**切分，最多 4 格（`CHAT_SPLIT_MAX_BUBBLES`），每格错开 120ms 淡入；落库仍是完整一条。只认段落分隔，代码围栏里的空行不切。

**提示词已对齐（2026-10-21）**：这条能力此前几乎从未被触发 —— `CHAT_RULES` 明令「一条回复不许出现空行」，而拆分器只认空行，两边正好互相抵消。该条现已改成：通常一段；确实有两三件独立的事要分开发时，用空行分成两到三个完整气泡，整条回复仍受一到三句的长度约束。默认形状仍是单气泡。

真人聊天的形状不是「一大段」，是**两三条短消息连发**。当时的想法与现状的偏差：

- 切分**在客户端**，按段落（不是按句子）切；间隔是 CSS 的 120ms，不是原设想的 300–800ms；没有「块数 ≤ 3 且每块 ≥ 8 字」那条门槛 —— 只要模型写了空行就分格，上限 4 格；
- **落库仍是完整一条**（同 §4.2 的理由：重进页面不该重演）；
- **原设计要求「设置里可关」，尚未实现**：这是当前唯一一处「默认开启且无法关闭」的表现层偏好，与删掉自动朗读的保守原则不完全一致；
- 与提示词里「一到三句」的关系：那条管整条回复的**长度**，空行只决定**形状**；长度上限不因分格而放宽，空行也不再被禁止。

### 4.4 情绪要落在多个通道

`mood` 现在只出一枚药丸（头部名字旁）。同一个信号可以用在四处：

| 通道 | 做法 | 成本 | 判断 |
|---|---|---|---|
| 药丸 | 已有 | — | 保留 |
| **语音语调** | mood → rate/pitch 的**微调表**（browser 档，[speech.ts](../src/lib/speech.ts)） | 约 0 | 已落地 |
| 头像表情 | 只作用在**大头像 / 空态**，不在气泡旁出表情图 | 中 | 未做；做，但别铺开 |
| 标点与句长 | 已经由提示词间接给了 | 0 | 顺带 |

两条纪律：**tts 档不要跟着情绪改音高** —— 那把嗓子是角色的身份，改它就等于换人；**药丸不要滥用** —— 情绪一旦每轮都有，就等于没有，缺标签时不出空壳已经是现在的做法。

### 4.5 长思考与声音

首字节前的呼吸光标已经有了。补一条：**超过 ~2.5 秒仍无 delta** 时，把那枚光标的呼吸周期放慢（表现「它在想」，而不是「它卡住了」）。**不要**伪造一条「……」消息：那是编内容，而且会与之后的回复打架。

朗读已落地，并且**刻意不做自动朗读** —— 理由不是成本，是**同意**：自动出声等于在一个用户没准备的时候替他决定「现在听」。这条也是「在场感」与「抢焦点」（§2.F）的分界线。自定义音色已落地，preset / describe / clone 三档都可选；这里只留一条当时的排序判断：**先 describe、后 clone** —— 因为前者不需要用户交出任何素材。

## 5. 能动性（最危险的一根柱子）

### 5.1 边界要存在，但不能变成「没空」

`persona.boundaries` + 「允许不友好」已经给了它拒绝的资格。再往前一步要设防：**允许短、冷、敷衍，不允许不回应。** 用户来这里是要陪伴的；一个天天没空、动不动已读不回的角色，在设定上很「像人」，在产品上是坏的 —— 那是最容易把「沉浸」做成「受挫」的地方。

### 5.2 photo 不只是发图功能

现在角色能不能发图，由 `emit_message_meta` 工具调用里的 `photo` 对象决定（[chatTools.js](../server/chatTools.js)、[chatPhoto.ts](../src/lib/chatPhoto.ts)）。这件事的沉浸感价值被低估了：

> **它是「它有过一段你没看见的时间」的证据。**

文字可以是即兴的，图不行 —— 图意味着它**当时真的在某个地方**。顺着这条推出几条低成本规则：

| 决定 | 为什么 |
|---|---|
| 提示词里补一条**地点连续性**：这一张和上一张别矛盾 | 一分钟前在阳台，一分钟后在雪山，比不发图更破功 |
| 频率**不设硬配额**是既定决定（2026-10-03） | 客户端至今没有「连续 N 轮最多一张」那类兜底，这一条不变。但把关的**判据**必须够严 |
| **默认「大多数消息里没有图」** | 2026-10-05 补。判据写成「你值得被看见」这种软话时，模型会一路认下来；必须把「没图是常态」直接写出来 |
| 连贯性收成**描述规则末尾的一个从句** | 它本来是独立规则，还举了「上一句在阳台、这一句在雪山」的例子 —— 那个例子**本身就在示范「每句都发图」** |
| 这一页的图**不该**让用户看见标签 | 元数据不进正文是对的。代价是「它没打算发图」与「发了但被丢弃」在界面上长得一样 —— 所以 DEV 下多打一行 `[chat] photo intent:`，那是唯一能一眼分辨的地方 |

> **2026-10-05 补记：一次真实的破功。** 地点连续性规则落地之后，用户报「每一句都会发图，没有发图的意图也会发」。诊断：标签在服务端就被剪掉，所以**问题只可能出在模型身上** —— 而那次改动同时干了两件推高照片存在感的事：把照片相关规则从 2 条加到 3 条（占规则块 1/4，且紧挨着「每条都要附 mood」那条），以及那个「阳台 / 雪山」的例子。已改成：判据收紧（「图是这条消息的重点」）、「没图是常态」写在最前、连贯性降级成一个从句、例子删掉。**教训**：给模型加规则时，**例子会被当成规范**；而「每条都要做的事」（mood）旁边的规则会被顺带执行。这套纪律现在落在 `photoRules`（[chatPhoto.js](../server/chatPhoto.js)）里，正文再也不教任何标签。

### 5.3 主动联系与虚拟生活：已砍（2026-10-19）

T6 主动联系与 T8 虚拟生活**不做**，不是「还没排期」。理由只有一条，且不可绕过：Kairo 本地优先、没有服务器、没有可信后台时钟 —— 页面关闭后角色无法发起任何消息，Web Push 又违背「无云、数据不出浏览器」的承诺。做一个只在页面开着时能「主动」的假通知，比不做更破功；T8 依赖 T6 的通道，随之一起砍。兴趣 / 习惯仍留在 persona 里，供对话时自然引用；设置页也不放一个点不动的通知开关。

留作决策记录、**当前不排期**的复活门槛（如果哪天前提变了，先过这张表再谈动手）：

| 条件 | 为什么 |
|---|---|
| **权限由角色在对话里申请**，而不是设置页里一个开关 | 「你要是想我，可以让我给你留话」—— 由它来问，是关系；由设置页来问，是配置 |
| 默认**关**，频率上限极低，且随时一击关闭 | 抢焦点不可逆：用户被吵一次就会关掉整个功能 |
| 内容必须**挂在一件真实发生过的事上**（引用记忆里的锚点） | 否则就是「随机问候」，那是最低级的拟人化 |
| 第一版只在**应用内**（回来时看见它在），不做系统推送 | 推送是「打断」，应用内是「它在等」 |

### 5.4 低风险的「它来起头」

不是异步推送，而是**对话内的主动性**：用户回了一个「嗯」「哦」「哈」，模型多半会跟着敷衍一句。补一条提示词规则：

> 用户只回了一两个字时，**换你带话题** —— 说一件你这边正在发生的事，或者接着上一个话题往下走。不要用「嗯」回应「嗯」。

成本 ≈ 0（一条规则），风险 ≈ 0（不异步、不抢焦点），收益明显 —— 能动性里**性价比最高的一条**，已落地。

## 6. 说 / 想 / 做：三层消息

### 6.1 定义与不对称

把「说 / 想 / 做」建成**三条独立的消息**，每条带一个 `layer` 字段（`say | think | act`），而不是把「想 / 做」用行内标签塞进正文里剪。

- **说（say）**：对话。双方可见、算「说出口的事实 / 承诺」、进长期记忆。每轮必有。
- **想（think）**：角色的内心独白。只对用户揭示，是**亲密感的来源 —— 来自不对称**：用户能窥见 ta 没说出口的话，但 ta 听不见用户的内心。
- **做（act）**：动作 / 旁白。第三人称的舞台提示（\*她把围巾绕紧\*）。是**共享世界里真发生的事**，双方都「经历」。

三条刻意不对称：**① 用户没有 `think`** —— 用户能「说」，但「想」只对角色开放，一旦允许用户发 `think`，就等于默许角色读心，拟人感立刻崩；这是保护拟人的护栏，不是功能缺失。**② 角色能记起自己的 `think`，但不该把它当「你已知的事实」引用** —— 隔几轮 ta 回头补一句「刚才我本想…」是加分；把内心当成公开承诺才是破功。**③ `think` 的内容不算对用户的承诺 / 事实**，它私密、可反悔，不能固化成长期「事实」。

### 6.2 为什么用消息级 `layer`，而不是再走一套行内标签

2026-10-20 前，`[photo:]` / `[mood:]` 是**值标签**：从一段正文里剪一枚意图，**附在这同一条消息上**。现在 mood / photo 已改走 `emit_message_meta` 的字段（见[角色对话.md](角色对话.md) §2.6），标签层只剩历史消息兼容；think / act 依然是**区域标记**，不走标签层。

think / act 不一样：**它们本身就是完整的一句独立表达**。硬塞进正文按位置剪，会把那个「切三路」的债再叠两枚 kind，而且让「开关展示 / 按层过滤记忆」变成一堆脆弱正则。做成消息级后：

- 展示开关 = **按 `layer` 过滤**，一行 filter，纯函数可测；
- 进不进记忆 = **压缩时按 `layer` 丢弃**，判据集中；
- 连发、reaction 本就是消息级，一以贯之。

**这条选择把 think / act 划在标签层之外**，所以它**不加重标签层的通用化债务**（见[System-Prompt.md](System-Prompt.md) §7）。`layer` 描述的是**话语的心理语域**；photo 是一条 `say` 消息携带的图片、mood 是 `say` 的属性 —— 都和它正交。

**产出机制（怎么从一轮里分出多层）**：模型在一轮回复里用**成对区域标记**划段，服务端按标记把这一轮**扇出成多条有序消息**，落到标记外的默认是 `say`。区域标记比值标签稳得多 —— 不需要位置白名单，一个 `currentLayer` 游标 + open/close 即可，天然免疫「位置切三路」的坑。模型忘闭合时，到轮尾按 `currentLayer` 收尾（复用 tailHold 思路）；错位的当正文，**宁多不可漏**。

### 6.3 数据模型（additive，不升 `DB_VERSION`）

```ts
// types.ts
type MessageLayer = 'say' | 'think' | 'act'
interface ChatMessage {
  // …existing
  layer?: MessageLayer   // 缺省 = 按 'say' 处理；载入时 coerce 空/未知值为 'say'
}
```

- 照 `origin` / `pinned` 的加法纪律：可选字段、不升 `DB_VERSION`（当前 14）、载入时把缺失 coerce 成 `'say'`，旧数据零迁移。
- think / act 各自是一条 `ChatMessage` 行，`text` 就是那句内心 / 那条动作；`role` 恒为助手（用户没有 think，act 本轮也归角色侧）。

### 6.4 逐层规则矩阵

| 层 | 产出条件 | 界面展示（默认） | 模型下一轮输入（短期上下文） | 进长期记忆（chat_summaries） |
|---|---|---|---|---|
| **say** | 每轮必有 | 恒展示 | 保留 | 保留（算事实 / 承诺） |
| **think** | 情绪浓、或「说的 ≠ 想的」时才有，**非每条** | **默认展示**，可全局关 | **保留**（ta 记得自己刚想过什么） | **不进** |
| **act** | **仅「场景模式」开启时产出** | 场景内默认展示，可关 | 保留（本轮动作是真实经历） | 只进**实质动作**；氛围动作压缩时丢弃 —— 这条过滤生产默认未启用，见 §6.8 |

三处留白的取舍理由：

- **think「不进长期摘要」但「留短期上下文」**：不进摘要，是为了别把主观内心固化成事实（免得「我其实嫌你烦」被永久摘要、日后被当承诺引用）；留短期，是因为角色记得自己上一轮想过什么很自然，连续性靠它。代价：越过滑动窗口后 ta 会「淡忘」具体内心，情绪残响交给 mood 层（[角色对话.md](角色对话.md) §5）承接，够用。
- **act「短期全留、长期只留实质」**：动作是共享事件，ta 不能对自己的行动失忆；但纯氛围（\*低头\* \*绕围巾\*）进摘要只会污染记忆。**区分「实质 / 氛围」只在蒸馏那一步用一个轻启发做，不要求模型每轮分类**，成本可控。
- **「关了展示会不会泄露」不算 bug**：act 事件真发生过，用户只是关掉美化文字；ta 引用那次动作是对的。展示开关只管**界面呈现**，不回写记忆 / 模型输入。

### 6.5 场景模式：`act` 的定位，也是那盏「信号灯」

规则记成一句：**日常模式 = say + think；场景模式 = say + think + act**。`act` 就是定义「是否进了场景」的那个 delta。

- **场景模式是一个显式状态 / 开关，由它 gate `act` 产不产出** —— 不要靠「模型这轮有没有打旁白」去反推点亮，否则 `act` 忽有忽无、信号灯会闪。灯跟着状态走，不跟着标签频率走。顺带解决了「现实里没人发微信还打星号配旁白」的出戏感：出戏只发生在日常模式，而日常模式本就不产出 `act`。
- 落地形状：**用户手动、角色级**的开关（键 `kimage.sceneMode`，默认关）。原设计的「角色驱动 + 用户 override」没有发生 —— `nextSceneMode` 的迟滞语义（首个 act 进入、边界离开）有纯函数与单测，生产无调用点。

### 6.6 触发与稀缺（油腻与否的命门）

- **think**：只在「内心 ≠ 口头」或情绪强烈时漏一句，非每条都写。触发阈值可直接接现有 mood 强度 —— 强情绪才允许内心泄露。
- **act**：场景内也是点缀节拍（开场定位、关键动作、转场），不是每句都旁白。
- 二者共用一条纪律：**能少则少**。满屏 think / act 会瞬间掉进三流同人文质感，稀缺才是亲密感。

### 6.7 视觉编码（人称 + 对齐 + 包裹，三重硬信号）

think 与 act 若都是「斜体 + 弱化色」，同屏必糊。拉开靠人称：

- **say** = 气泡（右 = 用户实心墨 `--accent`，左 = 角色白卡 + 细描边）。
- **think** = **第一人称**、无气泡、左缩进 + 一条细竖线、斜体弱化（「我停在那儿看了好久」）。
- **act** = **第三人称**、居中、星号 / 全角括号包裹、更弱（\*她把围巾又绕紧了一圈\*）；场景模式下整条 thread 可压一层极淡场景底。

人称差（「我…」vs「\*她…\*」）是模型一眼能判、用户一眼能分的硬信号，比颜色可靠。配色 / 暗色遵循现有 token：文字走 `--muted` / `--faint`，暗色下 `html[data-theme=dark]` 要提亮 fg 否则读不出；**别写死 `#fff`**（双主题反相坑）。

> 这三套编码是**普通页**的基准。沉浸页走另一套「剧本式排版」，那两条覆盖规则会把 `think` / `act` 的专属样式盖掉 —— 现状与缺口见 §7.2。

### 6.8 开关与落地状态

三枚开关都在**对话页菜单**里，不在设置页：`showThink` / `showAct` 是全局偏好（localStorage），`sceneMode` 是**角色级**。拨动展示开关**只看界面**，事件仍在、照喂下一轮、该记的还记。

| 项 | 状态 | 位置 |

| `ChatMessage.layer?` | 已加；缺省 coerce `say`，零迁移 | [types.ts](../src/types.ts) |

## 7. 页面骨架与实现

### 7.1 同一页的第二种骨架，不是第二个页面

| 决定 | 为什么 |
|---|---|
| **状态、消息、输入、流式全复用**，只换外层 chrome | 「再写一个对话页」的最后一定是两块逻辑互相漂移。这个仓库已经吃过两次：trapTab ×3、v-grow ×2 |
| **消息流是同一棵 DOM**，只改外层容器与 class | 不只是省事：`role="log"` 的 live region **只在它自己身上生效**。切模式时若把消息流整棵重造，读屏会把整段对话重新播报一遍 |
| 实现形状：一个 `immersive` 状态 → 外壳一个 class → ChatPage 一个 prop | 不用新的 store、不用新的路由、不用第二份 props |

### 7.2 减 / 加 / 守

**减（工具层，全部收走）**：

| 收走 | 为什么 |
|---|---|
| 顶栏（品牌 / 导航 / 主题开关） | 它是「站」的存在感。**但它是回别的页的唯一入口**，所以退出的门必须放大（§7.4） |
| 左栏角色列表 | 换人是「离开这段对话」，该有一点代价（已定：不留） |
| 头部的 Memory 药丸 | 它回答「它是怎么接的线」，不回答「它是谁」；2026-10-06 起 Model 药丸也收进了 项 菜单，名字下的身份描述一并去掉 —— 第二行只留给沉浸态的「场景 · 时间」 |
| .chat-main 的边框与底色 | 面板感就是工具感。对话该**浮在场景上**，不是装在框里 |
| 项 菜单（清空 / 编辑记忆 / 忘记） | 维护动作。退出一次很便宜，常驻很贵 —— **2026-10-05 改：项 在沉浸态留着**（「换一张背景」的入口就在那儿）。所以这一排里它是例外 |

**加（把画面还给角色）**：

| 加 | 为什么 |
|---|---|
| 它的正脸铺满背景 | 屏幕最大的那块面积归它，而不是归留白 |
| 一列 `--immersive-col: 660px`，**字靠左**、输入区居中 | 阅读宽度；参考图里字在左、人在右 —— 那个不对称就是它的构图，居中会把画面切成两半 |
| 两档字号：台词 20px（`--fs-xl`）、你的话 15px（`--fs-md`） | 这一页只有对话，没有别的东西抢层级；两个声音靠字号与明度分家 |
| 更松的行距与气泡间距 | 呼吸感来自「没有别的信息要挤」，不是来自装饰 |
| 极简头部：名字 · mood · 场景 · 时间（头像收起，退出钉右上） | 只留「我在跟谁说话、此刻在哪」这一个事实；那张脸已经是整块背景 |

**守（这一层不能跟着「沉浸」一起藏掉）**：notice / 错误提示 / 撤销条 /「回到最新 N new」/ 流式光标 / 情绪药丸 / 时间分隔 /「Last spoke 3 days ago」/ 每条消息的朗读键 / 生成中的 Stop。

> 朗读键（与它旁边那两枚）在这一页**挂在台词下面**，不在台词外侧：这一页的气泡是整列 100% 的，挂外侧就掉到字列右边压在剧照上，自己那条更糟 —— `right: 100%` 会把它甩到字列左边，窄屏上直接出屏。

> 一句话：**沉浸不是「看不见工具」，是「看不见不需要的工具」。**

#### 剧本式排版（2026-10-05 参考图定下的方向）

用户给的参考图（companion.app 的一屏）不是「聊天界面」，是**一页剧本压在剧照上**。落地时拆成下面几条；不做的也一并记着，免得下一个人以为是漏了。

| 参考里的 | 现状 |
|---|---|
| 锐利剧照铺满 | 已落，见 §7.3（不虚化；让位靠蒙版） |

| 靠字体音区认人 | 已落：角色 20px / `--text`，你 15px / `--text-2`，同一衬线族 `--font-serif` |

| 短窗渐隐 | 已落：消息流顶部 `mask-image` 渐隐 56px；流内时间分隔收掉，只留末尾 `away` 那条 |

| 麦克风 | 不做：语音输入维持「先放着」（§8.4） |

两处只有截图才发现的错：① 沉浸态的覆盖规则**必须放样式表最后** —— 同等特异度比先后，`.msg.assistant .bubble` 在中间时底色照旧漏出来；② 底与边是**一起给的**，只收底色会留下一圈细线框住每句台词。

**已知缺口（2026-10-20）**：这套排版定稿时还没有 `think` / `act`。现在沉浸态那两条覆盖规则（`.chat.is-immersive .bubble`、`.chat.is-immersive .msg.assistant .bubble`）位于样式表末尾且特异度不低于层样式，于是 `think` 的淡底与左竖线被收掉、`act` 被抬到台词的字号与亮度 —— 两者在同屏里都靠近 `say`（`act` 还留着斜体与居中）。要在沉浸页保住三层可分，得决定是补沉浸态样式、还是在沉浸态收起这两层；尚未做。

### 7.3 背景层：用它已有的正脸

`coverSrc(c.ref)` 就是它的正脸（ChatPage.vue 的 `avatarOf`），**字节已经在内存里** —— 不加请求、不加调用、不加钱。

| 正脸（ref） | 只有底图（sourceRef） | 两个都没有 / 加载失败 |
|---|---|---|
| 铺满 + 压暗 + 上下渐变蒙版 | 同上，用底图 | 主题色 + 极淡的纸纹（复用 bg-light / dark.webp），**静默退化** |

> **2026-10-05 补的退路**：原来只认正脸，而「只上传过一张图、还没生成过正脸」是很常见的一种角色 —— 那种角色切进沉浸页就是一片空的压暗色（用户的原话是「没有背景图啊」）。现在退到 sourceRef：它同样是「它长什么样」，有它也比只剩一层色强。

三条硬约束：

1. **对比度是硬约束，不是审美**：正文在最弱那一档背景下也要满足小字可读（约 4.6:1，见[设计系统.md](设计系统.md) §八）。压暗那一层就是为它存在的。
2. **别拿原图去 blur**。第一版用大虚化换可读性，结果把「这一场戏」整个糊没了 —— 而那一页的全部意思就在这场戏里。现在画面锐利，让位归蒙版：横向一道（左边重、右边接近透明）给文字，纵向两道给角色名与输入区；正文靠左、输入区居中，那个不对称就是参考图的构图。场景行收成**第一小句**（`a grey window at dawn · 11:43`，不是那整段出图提示词），流内的图再收小一档。
3. **一个旋钮 `--veil`**（默认 `.78`，挂在 `.chat-bg` 上）：白压到哪跟着文本栏走，不跟视口走 —— 人物那一侧（右三分之一）是 0。**代价如实记**：文本栏左端小字（`--text-2` `#6B6B6B`）的对比度随之落到约 4.4:1，本来就贴着 4.6:1 那条线。要提回去就把 `--veil` 往 `.85` 拨。

另外两条：**不做降采样**（存下来的就是 1280 的 JPEG，降到 1080 是空操作）；`.chat-bg` 固定定位铺满视口、`z-index: 0`，两层网格子项各自 `position: relative; z-index: 1` —— 不用负 z-index（那会跑到 body 背景之下，效果随浏览器绘制顺序而变）。

**背景图是单独生成、单独存的**（用户明确要求）：原来它借用消息里那张剧照，那是**角色发给你的照片**，构图是「随手拍给人的」；而背景图是**给字让位的底**。两件事诉求正好相反。

| | 生成什么 | 存在哪 | 什么时候生成 |
|---|---|---|---|
| 角色发的照片 | 按场景 + 镜头模板（自拍 / 他拍 / 空镜） | `chat_images`，跟着消息走；**另存一条历史记录** | 每次它想发图 |
| **对话背景图** | `planChatBackdrop`：横构图、主体靠右、左侧留给字 | `chat_backdrops`，一个角色一条；**另存一条历史记录** | **只有用户点 项 里的 New background** |

- **各存各的**：与设定图（charViews）、参考图（chars）、消息里的图（chat_images）互不相干 —— `chat_images` 按「消息引用到没有」回收，背景图混进去要么被当孤儿删掉，要么永远留着。两种图各自再落一条历史记录（`HistoryEntry.source = 'chat-photo'` / `'chat-backdrop'`），于是它们出现在历史页、首页图墙与角色页的作品墙上；这是**第二份字节**，两边生命周期不同。
- **一场戏一张**：记录里带着画它时用的那段场景描述，反复进出沉浸页不会重复付费。
- **什么时候画 —— 只有用户点的时候**：进沉浸页、换角色、对话里换了一场戏，一律**只把库里那张读回来铺上，不再自动出图**。依据是用户原话：「不需要每次进入沉浸页面就自动生图，只有我点击的时候才重新生成。」没有现成的就退到剧照 → 正脸 → 底图 → 主题色。
- **画不出来要如实说**（它是用户主动触发的动作，静默失败会让人以为按钮坏了）；**不加摄影指导那一层**（背景图自己已经把机位与光写死了，而那是一次额外的文本调用，正好压在「进沉浸页」这条路上 —— 那条路该尽量短）。

> 新增 `chat_backdrops` 时升过库（v11 → **v12**；当前 `DB_VERSION = 14`）。新增一张表是安全的：建表是同步的结构操作，没有重建表那种中途失败的风险。版本号只能升不能降。

|---|---|---|
| 入口 | 对话页头部最右一枚「展开」（与 项 同一排） | 与它要去的地方同一排，肌肉记忆连续 |
| 出口 | **两处**：同位置的「收起」、Esc（窄屏同一枚按钮） | 一个藏起出口的全屏模式就是把用户关在里面 |
| Esc 的层级 | 菜单 → 角色浮层 → **最后才是退出沉浸** | 接进既有的 `layerOnEscape`（[ui.ts](../src/lib/ui.ts)），沉浸模式是最外面那一层 |

| 焦点 | 进来交给输入框，出去还给那枚按钮 | 你进来是为了说话；焦点掉在文档开头是这家仓库一直在修的那类问题 |

| 离开对话页 | 偏好不动，这一页的 chrome 回到普通 | 顶栏必须回来 —— 它是去别的页（六页导航）的唯一入口 |

### 7.5 界面语言：拟人的归角色，实话的归系统

**已经做对的部分，不要动**：两侧气泡 + 靠说话人那侧收角、不逐条显示时间戳、只在跨天 / 超 30 分钟插分隔、自动跟随只在贴底时生效。这几条共同做了一件事：**让界面不解释自己**。

这是整篇里**最容易被做错**的一条。当配置缺失、上游报错、内容超长时，正确的做法**不是**把它拟人化（「我现在没力气说话」），而是：

| 层 | 说什么 | 例子 |
|---|---|---|
| 角色的世界（气泡、空态、输入提示） | 角色的话 | 它的回复、它的开场白 |
| 系统的世界（全局 notice、输入区那格警告） | **技术实话说人话** | 「这条超过 8000 字，它读不完」 |

理由有两条，缺一条都站不住：**对用户** —— 出错的时候他最需要的是确切信息，用角色口吻说，他连「该去修哪里」都读不出来；**对我们** —— 拟人化的错误一旦被识破，用户会开始怀疑**所有**角色说的话，包括本来是真话的那些（记忆、时间）。**信任是一次性的**。

落点是对的：错误走全局 `notice`，输入区就地出一格 52px 的警告，页面里不另开错误区。这条纪律要**继续扩到措辞**：让系统层的话**更少、更晚、更具体**，而不是更可爱。

2026-10-21 落地了这一条，口径固定成四句：位置一律写 **AI connections**（不再有 Settings / API settings / Interface Settings 三种叫法）；模型一律用设置页那五个用途名（Image generation / Role chat / Prompt enhancing / Image recognition / Voice）；配置缺口只有两种句式 —— 没配是 `Add a <Purpose> model in AI connections first.`，配了但缺字段是 `"<name>" is missing its <field> — fix it in AI connections.`；长错误只留**一个成因 + 一个下一步**。同类缺口尽量只留一个判据与一句模板，不在一处多查一项、另一处少查一项（出图那条就是 `imageConfigGap`，见 [api.ts](../src/api.ts)）。

**头部剩下的那枚 chip**（`Memory`，在 `head-acts` 那一排）回答的是真问题 ——「它记着多少」。但它是**工具语言**，常驻在角色名字旁边。折中，而不是二选一：

| 决定 | 为什么 |
|---|---|
| 保留可见性（不进 项 菜单） | 藏起来就等于「它记着多少」这个问题又答不上了 |
| 措辞中性、简短、**不带第一人称** | 不写 `from enhancing` 这种半句话；宁可写 `Borrowed` |
| 只在**变化时**才引人注意（如借用状态），平时压到最低对比度 | 一屏里最该显眼的是**谁在说话**，不是我们怎么接的线 |

**空态：给一个台阶，而不是一个空面板**。已有大头像 + 名字 + 一句**本地按 persona 拼的**开场白（不调接口）。仍未做的是下面再给 2–3 个由 persona 派生的可点话头、点一下即发送 —— 它解决「我不知道说什么」这一分钟的摩擦，而第一分钟决定沉浸；**话头必须是用户的口气**（伪造它发言是第一条禁忌）；三个上限，多了就变回「表单」。

**动效：新增内容的动画越少越好**。呼吸 = 在忙、药丸入场 = 情绪刚变化 —— 这两条有语义，保留。**不要**给消息加逐条入场动画：列表项滑入是「界面在表演」，而真实的消息是**突然出现的**。这与[设计系统.md](设计系统.md) 的「动效要说明状态，不是装饰」一致，只是在这里更严：装饰会直接破功。

**输入侧**：输入框就是「你说的话」，不要往里面塞工具条（表情面板、指令菜单会让它变成编辑器）；超长提示要说「它读不完」，不要说 `max 8000 chars`；语音输入（说给它听）维持「先放着」—— 支持面窄、识别不稳。

### 7.6 六个会打架的地方（真正动手时才会撞上）

**① 撤销条 vs 输入区 —— 量过了，确实打架，已修。** UndoToast 是 `bottom: 28px` 固定居中（[UndoToast.vue](../src/components/UndoToast.vue)），而聊天页的输入卡片也是**底部居中**。**实测（1280×900，探针量的）**：撤销条 828–872，输入卡片 811–859，**重叠 31px** —— 而且它不只难看：那一块**会吃掉点击**，想点进输入框打字的那一下会落在撤销键上，把刚删掉的东西又撤销回来。修法：`.undo.over-compose { bottom: 100px }`，类名由主界面按「当前是不是对话页」给（`page === 'chat'`）。值 = 输入卡片顶边到视口底的距离（约 92px）+ 一道缝。修完实测 `overlap: 0`。普通页其实也有同样的重叠 —— 这条修复顺带一起解决了，因为它挂的是「在对话页」而不是「在沉浸态」。

**② `--mast-h` 与高度算式（免费的一处，但有个坑）。** 顶栏用 **`v-show`** 藏掉时 `offsetHeight` 变 0，`mastRO` 会把 `--mast-h` 写成 `0px` —— **这一处不用额外改**。**但不能用 `v-if` 卸载顶栏**：换掉之后，坏的**不是沉浸页**而是普通页 —— 重新挂载那一次，观察者还挂在已经被摘掉的旧节点上，`--mast-h` 于是**永远停在 0**，而顶栏明明有 72px 高。症状是「普通页的面板高出 72px」。这个坑很安静：功能全对，只是差 72 像素。判别性检验落在**基线**上：`mastVisible` 为真时 `--mast-h` 必须非零。

**③ `role="log"` 的 live region。** 两个骨架**必须共用同一个消息流节点**。若沉浸态用 `v-if` 另造一棵树，切模式时读屏会把整段对话重新播报一遍。**这一条直接决定实现形状**：改外层容器与 class，不改消息流本身。

**④ 隐藏左栏之后，那条 240px 的轨道还在。** `.chat` 是 `grid-template-columns: 240px minmax(0, 1fr)`。把左栏 `display: none` **不会**让那一列塌掉 —— 显式的轨道宽度还在，右边会平白少 240px 再加一道 gap。沉浸态必须显式改 `grid-template-columns: minmax(0, 1fr)`。这是 CSS Grid 的常规行为，但症状是「右边窄了一截」，很容易被当成 padding 问题。

**⑤ `.shell-wide` 的 overflow。** 保持 `clip`（**不是 `hidden`**）：`hidden` 会让 `.shell` 变成滚动容器，聚焦底部输入框时浏览器可能把它滚一下（见[角色对话.md](角色对话.md) §3.4）。

**⑥ 把一个动作放进某个容器之前，先确认那个容器在这一档里是可见的。** 「换一张背景」的入口原本写在 项 菜单里，而「工具层收走」**把 项 一起藏了** —— 于是它永远点不到（用户原话：「没有换背景的按钮啊」）。现在 项 在沉浸态留着（参考图右上角那枚本来就是它），药丸仍然收起；探针补了两条断言：菜单在沉浸态**可见**、且里面确实有 `New background`。教训：这一条完全是靠「点一下看看」才会发现的，类型检查一句都不会说。

### 7.7 无障碍与窄屏

- **100dvh + `env(safe-area-inset-bottom)`**；键盘弹出时 dvh 会缩，消息流继续贴底。进 / 出只做**透明度**，不做缩放位移（`prefers-reduced-motion`）。
- 焦点与读屏、对比度的判据都在 §8.3：焦点是手测，live region 只测了节点身份（**读屏本身没有测**），对比度只有两种主题各拍一张的半自动替代 —— 背景是图片，取不到「计算样式里的背景色」。

## 8. 不做什么 / 验收 / 优先级 / 验证

### 8.1 不做的功能

| 不做 | 为什么 |
|---|---|
| 自动放音乐 / 打字音效 / 呼吸光晕 | 那是**表演**沉浸。而且「自动出声」这个站已经否过一次（删掉自动朗读） |
| 背景现画一张 AI 图 | 每次进入都花钱；它已有的正脸就是本人 |
| 第二套消息渲染 | 两份实现必然漂移，还会毁掉 live region 那条约束 |
| 把错误也「沉浸」掉 | 出错时用户最需要确切信息；用氛围盖住事实是欺骗（§7.5） |
| 把沉浸做成默认 | 默认值是最强的产品表达。存量用户没要求过这个，别替他决定 |
| 主动联系 / 虚拟生活 | 已砍（2026-10-19），见 §5.3 |

### 8.2 反模式：做完会一次花光沉浸感

| 做法 | 为什么错 |
|---|---|
| **伪造共同经历**（编一段「上次我们去海边」） | 与记忆直接冲突。用户一对照就发现整段关系是编的 —— 这是唯一一条**不可挽回**的错误 |
| **假装在线 / 假装忙 / 假装睡了** | 用户会测（发三条试试）。测出来之后，**所有**的「它在」都不可信 |
| 用慢换氛围（「打字慢一点更像人」） | 罚的是用户的时间；而且一旦他发现了，慢就等于坏 |
| 把技术错误拟人化 | 见 §7.5：出错时用户最需要确切信息 |
| 表情包、贴纸轰炸 | 把角色降级成 UI 装饰，还会掩盖「话本身不够像人」 |
| 情绪药丸每轮都有 | 情绪一旦恒定就等于没有 |
| 为了「像人」故意打错字、发一半撤回 | 不可控、不可测，而且用力过猛 —— 这是最容易自我感动的一类设计 |

一句话概括这一节：**所有「演出来的活人」都会在被识破的那一刻，把真的那部分一起带走。**

### 8.3 验收口径

沉浸感不能直接测，但**这几件可以**：

| 类型 | 判据 | 怎么取 | 状态 |
|---|---|---|---|
| 骨架真的换了 | 顶栏不可见、`--mast-h` 为 0、左栏不在布局里、单列 | 浏览器探针 | 已接 |
| 骨架换来的是**高度** | 沉浸态面板高 = 普通态 + 顶栏那 72px | 浏览器探针（比在视口高度上做文章稳：后者会被 min-height 盖过） | 已接 |
| 两个骨架没有漂移 | 消息流是**同一棵 DOM**：切模式前后给节点盖的戳还在 | 探针（`__probeStamp`） | 已接 |
| 背景层 | 沉浸态有 `.chat-bg img`（blob URL），普通态没有；没有正脸时退化成压暗色 | 探针 | 已接 |
| 工具层与出口 | Memory 药丸 / 可点换人入口收起；身份留下；项 与收起按钮在 | 探针 | 已接 |
| 破功没跟着藏 | 撤销条 /「回到最新」在沉浸态仍然可见可点；撤销条**不压输入区** | 探针（含重叠像素数） | 已接 |
| 整页仍钉死 | `.shell` 的 overflow 仍是 `clip`（§7.6 ⑤） | 探针 | 已接 |
| 对比度 | 两种主题下正文与背景 ≥ 4.6:1 | **仍没有自动判据**；替代是两种主题各拍一张（`measure-history.mjs --shot-dir`），用眼睛过一遍 | 半自动 |
| 读屏不重播 | live region 没被重建 | 探针覆盖「节点身份」，但**读屏本身没有测** | 半 |
| 焦点 | 进来落在输入框、出去回到那枚按钮 | 手测 | 半手测 |
| 记住偏好 | 偏好存本地；**在首页时不该沉浸**（顶栏是全站唯一出口） | 探针 | 已接 |

### 8.4 优先级

> **进度（2026-10-20）**：A 档五条均已落地；B 档的 ⑥ 连发气泡已落地但不带开关，⑧ 只做了「防本轮中途覆盖」；C 档的 ⑫ 已落地，⑪ 已砍，⑬ 暂缓，⑭ 仍放着。三条历史修正：③ 的落点从「空态」改到**消息流末尾**；① 顺带给照片场景提供了真实时间依据；⑤ 只补「地点连续性」、**没有补发图配额**。
>
> **2026-10-21**：⑩ 系统层措辞收敛已落地（口径见 §7.5）；B 档剩 ⑦ 头像表情、⑧ 的永久钉住、⑨ 开场话头。

| 档 | 项 | 成本 | 状态 |

| **A 现在做** | ① 时间注入 · ② 打字节奏器 · ③ 续接 · ④ mood → 语音语调 · ⑤ 提示词两条（接话题 + 地点连续性） | 低 | 五条全部已落地 |

### 8.5 怎么验证

沉浸感不能直接测，但**破功可以数**。

| 类型 | 指标 | 读法 |
|---|---|---|
| 破功 | 每会话出现的系统提示次数（notice 触发率） | 这是**主指标**，越低越好 |
| 破功 | 报错率、超长拦截率、限流命中率 | 每一条都是一次出戏 |
| 在场 | 首字节 P50 / P95 | §4.1 的预算 |
| 在场 | Stop 之后**继续留在这一页**的比例 | 按了停还留着 =「说到这儿够了」，不是失败 |
| 关系 | 人均轮次 / 会话、回访间隔 | 沉浸的角色会被聊很久、会被主动想起来 |
| 关系 | 角色切换率 | 频繁换人说明**没有一个真的留住他** |
| 关系 | 重生成率 | 想重听它怎么说 = 在意；过高则说明提示词不行 |

定性那条最准，也最简单：关掉页面十分钟，让用户复述刚才那段对话 —— **他复述的是「它说了什么」，还是「这个界面怎么用」**？还有一个更狠的自检：把这一页截屏**去色**、并**抹掉所有系统文案**，剩下的东西还像不像两个人的对话。

### 8.6 一句话

> **沉浸感 = 连续性 + 在场感 + 能动性 − 所有破功点。**
> 前五项靠喂（记忆、时间、节奏、情绪、声音、图），最后一项靠堵（标签、工具词、技术错误、抢焦点）。每加一样东西之前问一句：**这是在表现「它是个活人」，还是在表演「我们的界面很用心」？**
