# 对话沉浸感设计

> 这份文档回答一个问题：**怎么让用户忘了自己在用一个软件。**
> 它不提"氛围"，只列机制、破功点与取舍。
>
> 现状盘点基于这几处实现：[ChatPage.vue](../src/components/ChatPage.vue)、
> [useChat.ts](../src/composables/useChat.ts)、[App.vue](../src/App.vue) 的 `runChat`、
> [server/index.js](../server/index.js) 的 `chatSystemPrompt`、[server/chatTags.js](../server/chatTags.js)、
> [lib/speech.ts](../src/lib/speech.ts)、[lib/chatPhoto.ts](../src/lib/chatPhoto.ts)。
> 与 [角色对话功能设计.md](角色对话功能设计.md) 是同一件事的两面：那边写"有什么"，
> 这边写"像不像"。
>
> 风格判据沿用 [整体设计风格.md](整体设计风格.md)：
> **让能力隐藏，让过程自然。**

---

## 0. 先把词定死：沉浸感不是氛围

常见的误解是把沉浸感当成一种**视觉风格**：更暗的底、更柔的动效、更拟人的文案。
那些东西加不出沉浸感，只能掩盖破功点。

这一页真正发生的事情只有一件：**用户在跟一个人说话。**
所以沉浸感的操作性定义是——

> **沉浸感 = 用户不再意识到"界面"这一层的存在。**
> 换个说法：**沉浸感 ≈ 破功次数 ≈ 0。**

这条定义立刻给出方法论，也是这份文档的骨架：

| 步骤 | 做什么 | 为什么 |
| --- | --- | --- |
| **先减法** | 逐条堵住"出戏"的瞬间 | 破功是可以数出来的，氛围不可以。做减法可验收 |
| **后加法** | 供给"它是活的"的证据 | 只堵不漏的对话是"干净的应答机"，不是人 |
| **都不做** | 表演式的拟人化（贴纸、假状态、假在线） | 一旦被识破，**之前所有的"它在"都一起作废** |

三条判据，用来判断做没做对：

1. 用户关掉页面十分钟后复述这段对话，说的是**"它说了什么"**，而不是"我点了什么"；
2. 用户记不住刚才有没有等过 —— **Loading 留下的印象越淡越好**；
3. 用户会**主动回来**，而不是被通知叫回来。

第三条是分水岭：被通知叫回来的是工具，主动回来的是关系。

## 1. 三根支柱

| 支柱 | 用户心里在问 | 靠什么供给 | 破功长什么样 |
| --- | --- | --- | --- |
| **连续性** | 它还记得我吗？还是同一个人吗？ | 记忆（§7 已落地）、**时间**、人格一贯 | 复读机、失忆、"你刚才不是这么说的" |
| **在场感** | 它现在在这儿吗？ | 流式、打字节奏、情绪、声音、图 | 转圈、等 5 秒憋出一整段、面无表情 |
| **能动性** | 它是个人，还是个应答机？ | 拒绝、边界、有自己的事、会主动 | 每轮反问、"还有什么可以帮你的"、有求必应 |

> 还有第四个候选：**语境**（你们俩现在在哪儿、什么时候说话）。
> 它不单独立柱 —— "什么时候"属于连续性，"在哪儿"属于在场感，
> 分开会让这份文档多一栏而少一条可执行的东西。

这三条里，**连续性最省力、在场感最要紧、能动性最危险**：
前两条做错了只是"不像"，第三条做错了（主动消息、假装忙）会**直接毁掉关系**。

## 2. 破功清单 —— 这份文档最可执行的一节

营造沉浸感的工作步骤是：把这张表从上往下过一遍。

### A. 模型说漏

| 破功点 | 长什么样 | 对策 | 现状 |
| --- | --- | --- | --- |
| Markdown 泄漏 | 气泡里冒出 `**加粗**`、列表、标题 | `CHAT_RULES` 明令禁止（[server/index.js#L166-L176](../server/index.js#L166-L176)） | ✅ 已挡 |
| 元叙述 | `*sighs*`、`（皱眉）` | 同上："只写它会说出口的话" | ✅ 已挡 |
| 助手腔 | 每轮反问、"希望对你有帮助" | 同上 + 温度 0.9 | ✅ 已挡（软约束，偶发） |
| 标签泄漏 | 屏幕上划过去 `[photo:self:me on the bal` | `tailHold` 扣尾，绝不是按长度预留（[server/chatTags.js](../server/chatTags.js)） | ✅ 已挡，且踩过三次坑 |
| 人格漂移 | 聊五十轮后它变成通用助手 | persona 每轮都在 system 里 | ✅ 结构上已挡 |

这一组是**已经做对的部分**，值得原样守住：它们全靠提示词与 `chatTags` 那一层剪切，
而不是靠前端"看到标签就隐藏"。前者是根因，后者是创可贴。

### B. 管道漏出来

| 破功点 | 长什么样 | 对策 | 现状 |
| --- | --- | --- | --- |
| 等待无反馈 | 发完一句，界面上什么都没有 | 呼吸光标（`cursorId`，[ChatPage.vue#L247](../src/components/ChatPage.vue#L247)） | ✅ 已有 |
| 首字节过慢 | 等 5 秒一次性吐出来 | 流式已落地；**还没被当成产品指标** | ⚠️ 待办（§3.2.1） |
| 匀速吐字 | 字一个一个**均匀**出现 | 打字节奏器 | ❌ 未做（§3.2.2） |
| 技术错误 | `401`、`upstream timed out` 直接甩脸 | 已有 `failureMessage` 那套人话化 | ✅ 基本 |
| 配置缺失 | "Set a text model in API settings first" | 已分两种说（有配置 vs 没配置） | ⚠️ 措辞仍偏工具（§3.4.2） |

### C. 记忆与时间

| 破功点 | 长什么样 | 对策 | 现状 |
| --- | --- | --- | --- |
| 失忆 | 几十轮后忘了开头 | 摘要压缩（§7） | ✅ 已落地 |
| **没有时间感** | 隔了三天回来，它像上一秒还在说话 | system 里注入当前时间与间隔 | ❌ **未做，性价比最高**（§3.1.1） |
| 记忆被无声重写 | 用户改过的记忆下一轮又被润色 | 钉住（pin）机制 | ⚠️ 已记为未解决（§7.11） |
| 时序错乱 | "你昨天说的" —— 其实是三分钟前 | 同 §3.1.1 | ❌ 未做 |

### D. 状态被重置

| 破功点 | 长什么样 | 对策 | 现状 |
| --- | --- | --- | --- |
| 换设备就失忆 | 手机上打开，人还是那个人，记忆是空的 | 本地 IDB 的必然结果 | ✅ **如实说明即可，不要假装**（见 §5） |

这一条特别值得写进纪律：**做不到的事要明说，不要用氛围圆过去。**
"它记得什么"只存在这台设备上——这句话难听，但比让用户以为记忆丢了强。

### E. 用户被惩罚（这一组现在全部做对了，是本项目的范本）

| 破功点 | 对策 | 落点 |
| --- | --- | --- |
| 按 Stop 就删掉半句话 | **保留**已收到的字，标 `stopped` | [App.vue#L1543](../src/App.vue#L1543) |
| 撞上长度上限当成"正常说完" | 气泡下挂一行小注 | `finish === 'length'` |
| 报错吞掉用户打的字 | 本地先拦超长，原文留着 | `CHAT_MAX_CHARS` |
| 清空不可逆 | 走全局 UndoToast | 与删除角色同一套 |
| 重生成覆盖用户的选择 | `stopped` 的那条不给 Regenerate | — |

**"用户的操作永远不该被惩罚"** 是这三根支柱的地基：
一次"我打了字却被清空"，比十次破功都伤。

### F. 抢焦点

| 破功点 | 现状 |
| --- | --- |
| 自动朗读 | ✅ 曾经做过，**已删掉**（§8.4 记了这一笔：聊天是随手发生的动作，它不该在你没想到的时候开口） |
| 主动推送 | ❌ 未做，且明确"做不好会变成骚扰"（§8 方向 3） |
| 角标 / 红点 | ✅ 用的是 `N new` 而不是未读红点（§10.2） |

这一组的纪律：**注意力不是存在感。** 抢来的注意力换来的是"关掉整个功能"。

### G. 界面语言

| 破功点 | 长什么样 | 对策 |
| --- | --- | --- |

## 3. 落点

### 3.1 连续性

#### 3.1.1 时间注入（**先做这一条**）

现在 `chatSystemPrompt`（[server/index.js#L205](../server/index.js#L205)）里
**没有任何时间信息**。所以角色不知道现在是凌晨两点，也不知道上次说话是三天前 ——
而这两件事恰恰是真人在聊天里最先注意到的（"这么晚还没睡"）。

设计：

```
Right now: 2026-10-05 23:41, Sunday (the user's local clock, real world only — the story may be at another time).
You two last spoke 3 days ago.
```

| 决定 | 为什么 |
| --- | --- |
| **放在 `What you remember` 之前**，属"事实"那一层 | 它和记忆是同一类东西："发生过什么、现在是什么时候" |
| 由**前端算相对量**（"3 天前"），服务端只做拼装 | 时区在前端是对的，服务端不知道用户在哪儿；而且这与"人格字段由前端发结构、服务端拼提示词"是同一套分工 |
| **不要精确到秒** | `23:41:07` 是机器的时间。分钟已经够了，而且不会随请求漂移 |
| 有新鲜感上限 | 超过约 30 天没说话就不报间隔（"两个月前"会让它开口就 awkward）——退回只说当前时间 |
| 补一条规则："只在真的相关时提" | 否则它会**每轮**都说"现在是晚上" —— 比没有时间感更假 |
| **明确标注它只是"现实世界的钟"**（2026-10-08） | 剧情有自己的时间：现实里过了三分钟，剧情里可能过了三天。不划界，模型会拿现实时间推断剧情里的"现在"，把早已发生过的承诺重新当成待办（用户报的："已经过去的事又被说成等会要做"）。对应的规则是"现实钟不推进剧情"与"已经发生过的就不再是待办"（见 `CHAT_RULES`） |
| 首次对话（无上一条）只给当前时间 | 开场白因此能自然（"这个点还没睡？"） |

代价：几乎没有。收益：**每一条"时间感"的话都是真的**，这也正是它安全的原因 ——
它不编造任何事，只是知道了用户早就知道的事。

#### 3.1.2 记忆的锚点

现在记忆是"旧记忆 + 新消息 → 重写一份"（§7.5），
所以用户手改过的措辞会在下一轮被润色掉 —— 这一条已经被记为未解决（§7.11）。

落法：`ChatSummary` 加一个 `pinned?: boolean`（或一张极小的 `chat_facts` 表）。

- `pinned` 之后**不再把旧记忆喂回模型**，只让新消息往后接 —— 也就是那段文字停止进化；
- 界面上的差别只有一处：记忆块上多一枚"钉住"，改过之后自动点亮；
- 取舍要写清楚：**一旦钉住，它就永远是那句话**。这是"可信"与"会成长"的取舍，
  所以要**由用户按下去**，不能由我们替他决定。

顺带补一条**它自己该记住什么**的规则：名字、地点、承诺、欠下的账（§7.5 已有）。
这三样正是"三天后回来还追着你要"的东西 —— 记忆的取舍标准不是信息量，是**可追讨性**。

#### 3.1.3 回到对话的续接

**落点改了（2026-10-05，实现时才发现）。** 原稿写的是"空态里补一行"，
但空态只在**一条消息都没有**时出现（[ChatPage.vue](../src/components/ChatPage.vue) 的
`v-if="!msgs.length"`）—— 也就是说，恰恰在"有一段旧对话要接上"的时候它不出现。
这一条的落点因此改成**消息流的末尾**：

```
      "……"
      "路上小心。"
  Last spoke 3 days ago        ← 补这一行
┌──────────────────────────┐
│  输入区                    │
```

| 决定 | 为什么 |
| --- | --- |
| 补在**末尾**，不在顶上 | 回来时眼睛落在最新那一条上，而顶部要往上翻才看得到 |
| **不引用最后一句**（原稿想写「…最后一句…」） | 那一条就在它上面一格 —— 复述一遍是纯噪声 |
| 阈值沿用时间分隔那条（30 分钟） | 刚聊完去别处转一圈回来不该看见它；而它一旦出现，就是"这不是接着刚才说的" |
| 措辞与**角色被告知的那句同源**（`agoLabel`，[server/chatTime.js](../server/chatTime.js)） | 同一个事实在界面与提示词里说成两样，用户会以为它们在讲两件事 |
| 超过 30 天换成"2 months ago"这一档粒度 | 隔了半年还说 `183 days ago` 是机器在报数 |
| **纯本地派生，不调模型** | 一进页面就花钱不对（这条已在开场白那处定过） |
| 措辞是"Last spoke"而不是"History" | 前者是关系，后者是数据库 |
| **不替角色说话** | 不要写成"它说：快回来" —— 那是伪造它的发言，属于 §5 的第一条禁忌 |

> **顺带发现（未修，记一笔）**：进页面时消息是**异步**从 IndexedDB 读的，
> 而空态只看 `!msgs.length` —— 所以每次进入一个**聊过**的角色，
> 都会有一瞬间的 "Say something to X"，随后被消息流替换掉。
> 本地读通常快到看不见，所以它是一条**潜在**的闪烁而不是现行缺陷；
> 真要修得给"还没读完"一个与"真的没有"不同的状态。

#### 3.1.4 遗忘要有叙事

`Forget memory` 之后角色是真的不记得了（§7.9），这是对的。
补一条纪律：**忘掉之后不要在提示词里安排它"想不起来"**（"我不记得你说过"）——
那是在演失忆。让它**自然地不问、不接**就够了：真人忘了事，是不会主动宣布的。

### 3.2 在场感

#### 3.2.1 首字节预算要变成一个数字

流式是这一页**最重要的一步**（§0 那句"等 5 秒憋出一整段，拟人感当场崩掉"）。
但"用了流式"不等于"够快"：真正决定观感的是**首字节延迟（TTFB）**。

建议把它当成一条产品指标看待：**P50 < 1.2s，P95 < 3s**，超出的部分才需要表现层补。
在此之前不要用假的"正在输入…"去掩盖慢 —— 那会让慢变得可以忍受，于是没人去修。

#### 3.2.2 打字节奏器（客户端，纯表现层）

现在的路径是 `onDelta: (delta) => { reply.content += delta }`
（[App.vue#L1526](../src/App.vue#L1526)）—— 增量到即渲染，
所以**吐字速度 = 模型的吐字速度**，而模型是匀速的。
**匀速正是"机器感"的来源**：真人打字是有节奏的，句末会停，想事情会停。

设计一个只做"延后"的节奏器：

| 规则 | 值 |
| --- | --- |
| 句末标点（`。！？.!?`）之后 | 120–260ms |
| 逗号、顿号、破折号之后 | 60–140ms |
| 换行 / 段落之前 | 200–400ms |
| 抖动的来源 | **用 `msg.id` 做哈希**，不用 `Math.random()` |

| 决定 | 为什么 |
| --- | --- |
| **只延后，不加速，且总延迟封顶**（如 ≤ 1.2s） | 目的是消除"匀速"，不是让人多等。超出预算就直接放行 |
| 哈希取抖动，不取随机 | 同一个 id 重播一致、可测；也让"重生成"能拿到另一条节奏 |
| 页面不可见（`document.hidden`）时**直接放行** | 没人在看的时候不该攒着 |
| 节奏器只活在**渲染层** | 落库的是完整正文（[App.vue#L1574](../src/App.vue#L1574) 一次写入）—— 重新进页面时不会重演一遍打字，那是鬼畜 |
| Stop 时**立即冲刷**剩余缓冲 | 按了停还慢慢吐字是惩罚用户 |

这条之所以值得单列：它是**唯一一条不改模型、不改提示词、不改成本就能去掉机器感**的改动。

#### 3.2.3 连发气泡（B 档，但收益很大）

真人聊天的形状不是"一大段"，是**两三条短消息连发**。
现在一到三句挤在一个气泡里 —— 内容对了，形状不对。

- 切分**在客户端**，按段落 / 句子切成 2–3 块，间隔 300–800ms 逐个出现；
- **落库仍是完整一条**（同 §3.2.2 的理由：重进页面不该重演）；
- 只在"块数 ≤ 3 且每块 ≥ 8 字"时才切，宁可少切也不要切碎一句话；
- 必须是设置里**明确可关**的一项：有人就是讨厌这个，而这是**表现层**的偏好，
  没有"正确"答案（对照 §8.4 删掉自动朗读的教训：默认行为要保守）。

与提示词里"一到三句"的关系：那条管**长度**，这条管**形状**，不冲突。

#### 3.2.4 情绪要落在多个通道

`mood` 现在只出一枚药丸（头部名字旁）。同一个信号可以用在四处：

| 通道 | 做法 | 成本 | 判断 |
| --- | --- | --- | --- |
| 药丸 | 已有 | — | ✅ 保留 |
| **语音语调** | `mood` → `rate`/`pitch` 的**微调表**（browser 档，[lib/speech.ts](../src/lib/speech.ts)） | ≈ 0 | ✅ 先做 |
| 头像表情 | 只作用在**大头像 / 空态**，不在气泡旁出表情图 | 中 | ⚠️ 做，但别铺开 |
| 标点与句长 | 已经由提示词间接给了 | 0 | ✅ 顺带 |

两条纪律：

- **tts 档不要跟着情绪改音高** —— 那把嗓子是角色的身份，改它就等于换人；
- **药丸不要滥用**：情绪一旦每轮都有，就等于没有。缺标签时不出空壳已经是现在的做法（§8.1），守住它。

#### 3.2.5 长思考要有不同的表现

首字节前的呼吸光标已经有了。补一条：**超过 ~2.5 秒仍无 delta** 时，
把那枚光标的呼吸周期放慢（表现"它在想"，而不是"它卡住了"）。

**不要**伪造一条"……"消息：那是编内容，而且会与之后的回复打架。

#### 3.2.6 声音：永远手动

朗读已落地，并且**刻意不做自动朗读**（§8.4）—— 这条要一直守住。
理由不是成本，是**同意**：自动出声等于在一个用户没准备的时候替他决定"现在听"。
这条纪律也是"在场感"与"抢焦点"（§2.F）的分界线。

自定义音色（§8.5）是这条路上最大的一档收益，设计已定，按原计划走即可。
这里只补一条排序判断：**先 `describe`、后 `clone`** —— 与那份文档一致，
因为前者不需要用户交出任何素材。

### 3.3 能动性（最危险的一根柱子）

#### 3.3.1 边界要存在，但不能变成"没空"

`persona.boundaries` + "允许不友好"已经给了它拒绝的资格。
再往前一步要设防：**允许短、冷、敷衍，不允许不回应。**
用户来这里是要陪伴的；一个天天没空、动不动已读不回的角色，
在设定上很"像人"，在产品上是坏的 —— 那是最容易把"沉浸"做成"受挫"的地方。

#### 3.3.2 `[photo:…]` 不只是发图功能

现在角色能在回复末尾带一枚照片意图（[server/chatTags.js](../server/chatTags.js)、
[lib/chatPhoto.ts](../src/lib/chatPhoto.ts)）。这件事的沉浸感价值被低估了：

> **它是"它有过一段你没看见的时间"的证据。**

文字可以是即兴的，图不行 —— 图意味着它**当时真的在某个地方**。
顺着这条推出两条低成本规则：

| 决定 | 为什么 |
| --- | --- |
| 提示词里补一条**地点连续性**：这一张和上一张别矛盾 | 一分钟前在阳台，一分钟后在雪山，比不发图更破功 |
| 频率**不设硬配额**是既定决定（2026-10-03） | 客户端至今没有"连续 N 轮最多一张"那类兜底，这一条不变。但把关的**判据**必须够严 —— 见下面那条补记 |
| **默认"大多数消息里没有图"** | 2026-10-05 补。判据写成"你值得被看见"这种软话时，模型会一路认下来；必须把"没图是常态"直接写出来 |
| 连贯性收成**描述规则末尾的一个从句** | 它本来是一条独立规则，还举了"上一句在阳台、这一句在雪山"的例子 —— 那个例子**本身就在示范"每句都发图"**。挪进从句之后既保住了连贯，又不再给模型一个"图是常态"的样例 |
| 这一页的图**不该**让用户看见标签 | 服务端剪掉是对的（`[photo:…]` 是元数据）。代价是"它没打算发图"与"发了但被剪掉"在界面上长得一样 —— 所以 DEV 下多打一行 `[chat] photo intent:`，那是唯一能一眼分辨的地方 |

> **2026-10-05 补记：一次真实的破功。** 上面那条"连贯性"规则落地之后，
> 用户报"每一句都会发图，没有发图的意图也会发"。
> 诊断：标签在服务端就被剪掉，所以**问题只可能出在模型身上** ——
> 而那次改动同时干了两件推高照片存在感的事：把照片相关规则从 2 条加到 3 条
> （占规则块 1/4，且紧挨着"每条都要附 mood 标签"那条），
> 以及那个"阳台 / 雪山"的例子。已改成：判据收紧（"图是这条消息的重点"）、
> "没图是常态"写在最前、连贯性降级成一个从句、例子删掉。
> **教训**：给模型加规则时，**例子会被当成规范**；而"每条都要做的事"
> （mood 标签）旁边的规则会被顺带执行。

#### 3.3.3 主动消息：先把边界写死再动手

未做，且明确记着"做不好会变成骚扰"（§8 方向 3）。这里是它的准入门槛，
**不满足就先别做**：

| 条件 | 为什么 |
| --- | --- |
| **权限由角色在对话里申请**，而不是设置页里一个开关 | "你要是想我，可以让我给你留话" —— 由它来问，是关系；由设置页来问，是配置 |
| 默认**关** | 抢焦点不可逆：用户被吵一次就会关掉整个功能 |
| 内容必须**挂在一件真实发生过的事上**（引用记忆里的锚点） | 否则就是"随机问候"，那是最低级的拟人化 |
| 频率上限极低（如最多每 N 天一条），且**随时一击关闭** | 同第一款 |
| 第一版只在**应用内**（回来时看见它在），不做系统推送 | 推送是"打断"，应用内是"它在等" |
| **做不出来就先不做** | 这条不是保守，是这份文档 §5 第一条的直接推论 |

#### 3.3.4 低风险的"它来起头"

不是异步推送，而是**对话内的主动性**：用户回了一个"嗯""哦""哈"，
现在模型多半会跟着敷衍一句。补一条提示词规则：

> 用户只回了一两个字时，**换你带话题** —— 说一件你这边正在发生的事，
> 或者接着上一个话题往下走。不要用"嗯"回应"嗯"。

成本 ≈ 0（一条规则），风险 ≈ 0（不异步、不抢焦点），收益明显 ——
这是能动性里**性价比最高的一条**。

### 3.4 界面与语言：让界面这一层隐形

#### 3.4.1 已经做对的部分，不要动

两侧气泡 + 靠说话人那侧收角、不逐条显示时间戳、只在跨天/超 30 分钟插分隔、
自动跟随只在贴底时生效 —— 这几条是这一页最正确的决定（[ChatPage.vue](../src/components/ChatPage.vue)）。
它们共同做了一件事：**让界面不解释自己**。

#### 3.4.2 拟人的归角色，实话的归系统

这是这份文档里**最容易被做错**的一条。当配置缺失、上游报错、内容超长时，
正确的做法**不是**把它拟人化（"我现在没力气说话"），而是：

| 层 | 说什么 | 例子 |
| --- | --- | --- |
| 角色的世界（气泡、空态、输入提示） | 角色的话 | 它的回复、它的开场白 |
| 系统的世界（全局 `notice`、输入区那格警告） | **技术实话说人话** | "这条超过 8000 字，它读不完" |

理由有两条，缺一条都站不住：

- **对用户**：出错的时候他最需要的是确切信息。用角色口吻说，他连"该去修哪里"都读不出来；
- **对我们**：拟人化的错误一旦被识破，用户会开始怀疑**所有**角色说的话 ——
  包括本来是真话的那些（记忆、时间）。**信任是一次性的。**

现在的落点是对的：错误走全局 `notice`，输入区就地出一格 52px 的警告，页面里不另开错误区
（§3.4.6）。这条纪律要**继续扩到措辞**：让系统层的话**更少、更晚、更具体**，
而不是更可爱。

#### 3.4.3 头部的两枚 chip

`Model` 与 `Memory` 两枚药丸（§3.4.10 的 `head-acts`：模型 · 记忆 · ⋮）回答的是真问题
——"现在是谁在说话""它记着多少"。但它们是**工具语言**，常驻在角色名字旁边。

折中，而不是二选一：

| 决定 | 为什么 |
| --- | --- |
| 保留可见性（不进 ⋮ 菜单） | 藏起来就等于"它走的哪个模型"这个问题又答不上了 |
| 措辞中性、简短、**不带第一人称** | 不写 `from enhancing` 这种半句话；宁可写 `Borrowed` |
| 只在**变化时**才引人注意（如借用状态），平时压到最低对比度 | 一屏里最该显眼的是**谁在说话**，不是我们怎么接的线 |

#### 3.4.4 空态：给一个台阶，而不是一个空面板

已有：大头像 + 名字 + 一句**本地按 persona 拼的**开场白（不调接口）。
补一步：下面给 **2–3 个由 persona 派生的可点话头**，点一下即发送。

- 它解决的是"我不知道说什么"这一分钟的摩擦 —— 第一分钟决定沉浸；
- **话头必须是用户的口气**，不能写成角色的话（伪造它发言，§5 第一条）；
- 三个上限。多了就变回"表单"。

#### 3.4.5 动效：新增内容的动画越少越好

呼吸 = 在忙、药丸入场 = 情绪刚变化 —— 这两条都有语义，保留。

**不要**给消息加逐条入场动画。列表项滑入是"界面在表演"，
而真实的消息是**突然出现的**。这一条与 [整体设计风格.md](整体设计风格.md) 的
"动效要说明状态，不是装饰"完全一致，只是在这里更严：装饰会直接破功。

#### 3.4.6 输入侧

- 输入框就是"你说的话" —— 不要往里面塞工具条（表情面板、指令菜单会让它变成编辑器）；
- 超长提示要说"它读不完"，不要说 `max 8000 chars`（同 §3.4.2）；
- 语音输入（说给它听）维持现有判断：支持面窄、识别不稳，先放着（§8.4）。

## 4. 优先级

> **进度（2026-10-05）**：A 档五条**已全部落地**（T6.0–T6.5，见
> [优化计划.md](优化计划.md) 的 Phase 6）。三条修正记在那份计划里：
> ③ 的落点从"空态"改到了**消息流末尾**（§3.1.3 已重写）；① 的实现顺带
> 给照片场景提供了真实的时间依据（§3.3.2）；⑤ 只补"地点连续性"、
> **没有补发图配额** —— 频率不设上限是既定决定。
> 还没验完的：首字节的真实数字（尚无），以及三条只能手测的提示词/听感项。

| 档 | 项 | 成本 | 为什么在这个位置 |
| --- | --- | --- | --- |
| **A 现在做** | ① 时间注入（§3.1.1） | 低 | 每句时间感的话都是真的，且不可被识破 |
| | ② 打字节奏器（§3.2.2） | 低 | 唯一不改模型就能去掉机器感的改动 |
| | ③ 回到对话的续接（§3.1.3） | 低 | 零模型调用，入口那一秒的体验 |
| | ④ `mood` → 语音语调（§3.2.4） | 低 | 已有一套信号，白用 |
| | ⑤ 提示词补两条：接话题 + 地点连续性（§3.3.4 / §3.3.2） | ≈0 | 两条规则换两块收益 |
| **B 接着做** | ⑥ 连发气泡（§3.2.3） | 中 | 形状比内容更像人，但要可关 |
| | ⑦ 头像表情（§3.2.4） | 中 | 只作用在大头像上 |
| | ⑧ 钉住记忆（§3.1.2） | 中 | 兑现已记录的那条未解决风险 |
| | ⑨ 开场话头（§3.4.4） | 低 | 降第一分钟的摩擦 |
| | ⑩ 系统层措辞收敛（§3.4.2/3.4.3） | 低 | 破功点里的长尾 |
| **C 想清楚再动** | ⑪ 主动消息（§3.3.3） | 高 | 先满足准入条件 |
| | ⑫ 自定义音色 | 高 | 设计已定（§8.5），按原顺序走 |
| | ⑬ 多段会话 | 中 | 设计已定稿（§8.2），**暂缓** |
| | ⑭ 语音输入 | 高 | 维持"先放着" |

一个判断：**A 档五条加起来，比 C 档任何一条都更能提升沉浸感**，
而且没有一条需要新的后端端点。所以先把 A 走完。

## 5. 反模式：做完会一次花光沉浸感

| 做法 | 为什么错 |
| --- | --- |
| **伪造共同经历**（编一段"上次我们去海边"） | 与记忆直接冲突。用户一对照就发现整段关系是编的 —— 这是唯一一条**不可挽回**的错误 |
| **假装在线 / 假装忙 / 假装睡了** | 用户会测（发三条试试）。测出来之后，**所有**的"它在"都不可信 |
| 用慢换氛围（"打字慢一点更像人"） | 罚的是用户的时间；而且一旦他发现了，慢就等于坏 |
| 把技术错误拟人化 | 见 §3.4.2：出错时用户最需要确切信息 |
| 自动出声 / 自动推送 | 抢注意力不是营造存在感；已被验证过一次（§8.4） |
| 表情包、贴纸轰炸 | 把角色降级成 UI 装饰，还会掩盖"话本身不够像人" |
| 逐条消息入场动画 | 界面在表演（§3.4.5） |
| 情绪药丸每轮都有 | 情绪一旦恒定就等于没有 |
| 为了"像人"故意打错字、发一半撤回 | 不可控、不可测，而且用力过猛 —— 这是最容易自我感动的一类设计 |

一句话概括这一节：**所有"演出来的活人"都会在被识破的那一刻，把真的那部分一起带走。**

## 6. 怎么验证

沉浸感不能直接测，但**破功可以数**。

| 类型 | 指标 | 读法 |
| --- | --- | --- |
| 破功 | 每会话出现的系统提示次数（`notice` 触发率） | 这是这份文档的**主指标**，越低越好 |
| 破功 | 报错率、超长拦截率、限流命中率 | 每一条都是一次出戏 |
| 在场 | 首字节 P50 / P95 | §3.2.1 的预算 |
| 在场 | Stop 之后**继续留在这一页**的比例 | 按了停还留着 = "说到这儿够了"，不是失败 |
| 关系 | 人均轮次 / 会话、回访间隔 | 沉浸的角色会被聊很久、会被主动想起来 |
| 关系 | 角色切换率 | 频繁换人说明**没有一个真的留住他** |
| 关系 | 重生成率 | 想重听它怎么说 = 在意；过高则说明提示词不行 |

定性那条最准，也最简单：

> 关掉页面十分钟，让用户复述刚才那段对话。
> **他复述的是"它说了什么"，还是"这个界面怎么用"。**

还有一个更狠的自检：把这一页截屏**去色**、并**抹掉所有系统文案**，
剩下的东西还像不像两个人的对话。

## 7. 一句话

> **沉浸感 = 连续性 + 在场感 + 能动性 − 所有破功点。**
> 前五项靠喂（记忆、时间、节奏、情绪、声音、图），最后一项靠堵（标签、工具词、技术错误、抢焦点）。
>
> 每加一样东西之前问一句：
> **这是在表现"它是个活人"，还是在表演"我们的界面很用心"？**
