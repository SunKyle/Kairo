# 对话里「角色发一张图」：六层拼装详解

> 状态：**与当前代码一致**（2026-10-08 梳理）。
> 本文只拆一件事：[`planChatPhoto`](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L678) 这一层——把一句场景描述拼成真正发给图像模型的整段提示词。
> 上游（标签协议、`splitTags`）与下游（取参考图、发请求、摄影指导）只在**接缝处**点到为止，各自另有详述。
> 每个决定的**为什么**，见 [角色配图构图与光影设计.md](file:///Users/sunxiaokai/Desktop/project/KImage/doc/角色配图构图与光影设计.md)；本文着重**结构与不变量**。

## 零、一句话定位

这一层回答一个问题：**「这一张照片，文字部分该长什么样」**。

它把四个输入——场景、有没有它本人、谁拿的相机、离得多近——摊成**一串带槽名的层**，再拼成一段字符串。

```
输入                                         输出
─────────────────────────                   ────────────────────────────
scene   一句话场景（模型写的，永不改写）  ─▶  prompt    真正发给上游的整段
self    画面里有没有它本人              ─▶  useRefs   要不要发设定图当参考图
shot    谁拿的相机（标签给 / 场景判）    ─▶  shot      最终定下的视角（摄影指导可能改）
frame   离得多近（标签给 / 场景判）      ─▶  frame     最终定下的景别（谁都不许改）
anchor  身份锚点句（characterAnchor）    ─▶  self / scene
gender  性别（只在特写用）               ─▶  layers    分层结构（摄影指导按它逐位替换）
mood    这一刻的心情（只在有脸时用）
```

签名（[chatPhoto.ts L678](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L678)）：

```ts
export function planChatPhoto(
  scene: string,
  self: boolean,
  anchor = '',
  shot?: ChatShot,
  frame?: ChatFrame,
  gender = '',
  mood = ''
): ChatPhotoPlan
```

> 没有场景就直接返回空提示词（`prompt: ''`, `useRefs: false`）——调用方据此放弃这一张，而不是拼出一段只剩外貌的提示词（那会画出一张没有场景的人像）。

## 一、六层总览

文件头把这套结构叫「**六层提示词**」。它是**职责分组**的说法；落到代码里是 **13 个带槽名的层**。两者对照如下（**顺序即权重，不能反**）：

| 层（概念） | 具体槽（`layers[i][0]`） | 出现条件 | 内容来源 | 摄影指导可否改 |
| --- | --- | --- | --- | --- |
| ① 媒介与视角 | `medium` | 总是 | 模板 `tpl.medium` | ✘ |
| ② 内容 | `scene` | 总是 | 上游标签（**永远原样**） | ✘ |
| ③ 身份 | `anchor` | `self && 锚点非空` | `characterAnchor` | ✘ |
| ③ 身份 | `expression` | `self && frame≠close && 心情合法` | `expressionLine(mood)` | ✘ |
| ③ 身份 | `part` | `self && frame==close` | `partLine(gender)` | ✘ |
| ④ 不可让渡 | `pin` | 模板有 `pin`（三档都有） | 模板 `tpl.pin` | ✘ |
| ④ 不可让渡 | `frame` | 总是 | `frameLine(self, frame)` | ✘ |
| ⑤ 工艺 | `camera` | 总是 | 模板 or `FRAMING` 覆盖 | ✔ 可整句替换 |
| ⑤ 工艺 | `lens` | 场景没说镜头 | 模板 or `FRAMING` 覆盖 | ✔ |
| ⑤ 工艺 | `light` | 场景没说光 | 模板 / `lightWet` / 覆盖 | ✔ |
| ⑤ 工艺 | `env` | 总是（无条件） | 模板 or `FRAMING` 覆盖 | ✔ |
| ⑤ 工艺 | `action` | 场景没说动作、非特写、**且场景不是中文** | 模板 `tpl.action` | ✘ |
| ⑥ 约束 | `negative` | 总是（垫最末） | `NEGATIVE` 常量 | ✘ |

**四条读法**（写错了都会"图不对味但不报错"）：

1. **顺序即权重**：越靠前对图像模型越硬。所以"这一张要画什么"（`scene`）永远在"这个人是谁"（`anchor`）之前。
2. **槽名 = 权限**：摄影指导只认 `camera/lens/light/env` 四个槽，其余槽它**结构上拿不到**（见 §十）。
3. **只补不覆盖**：`lens`/`light` 只在场景确实没说时才出现（见 §八）。
4. **负面约束垫最后**：整段被截断时，它是最后一个被丢的（见 §九）。

## 二、① 媒介与视角层：`medium`

`medium` 说**用哪种媒介成像**，并且承载"这是手机拍的"这层语境。

| 视角 | `medium` |
| --- | --- |
| `selfie` | `photographic, shot on a phone front camera` |
| `third` | `photographic, a casual snapshot taken on a phone by somebody else` |
| `scene` | `photographic` |

**为什么排最前**：图像模型没有"自拍"这个概念，它只有"画一个人"。能把"画一个人"掰成一张自拍的，是 `front camera` 这类具体的词。这一层先定介质与拍摄方式，后面的 `camera` 再补距离与机位。

**注意 `style` 不在这里、也不在锚点句里**：中介质由这一层给（`photographic`），角色设定里的 `style`（anime / photorealistic…）刻意不进对话出图链——两边都写会重复，重复且措辞不一致时模型会丢掉一个（`characterAnchor` 的值也不含 `style`）。

## 三、② 内容层：`scene`

**场景原文一字不改地进来，而且永远在第二个位置。**

- 它是"这一张画的是什么"，是用户的意图，不是可以优化的东西——**任何一层都不许改写它**（摄影指导那层也是拿到它作输入、但只回写另外四位）。
- 排第二（在 `medium` 之后、`anchor` 之前）是有意的：它必须**在身份锚点之前**。反过来写等于把固定的长相顶在最前面，"这一张画什么"被压到最后（与创作区的 `composedPrompt` 是同一条纪律）。
- 上游已经把场景收敛成一行、截到 `PHOTO_SCENE_CHARS = 400`（[chatTags.js](file:///Users/sunxiaokai/Desktop/project/KImage/server/chatTags.js#L39-L52)）；这一层只做 `replace(/\s+/g,' ').trim()`。

## 四、③ 身份层：`anchor` / `expression` / `part`

三层说的是同一件事的两面：**"这个人是谁"** 与 **"此刻他/她什么样"**。三者都只在"画面里有人"（`self`）时才可能出现。

### 4.1 `anchor`：身份锚点句

- 来源 [`characterAnchor(c)`](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L170-L176)：从结构化设定里只取 **9 项**，顺序即优先级：
  `face → hair → eyes → brows → noseMouth → facialHair → faceMarks → marks → build`。
- `faceMarks` / `marks` 是 2026-10-08 并入的：它们是用户亲手写下的身份特征（脸上的痣/疤、身上的纹身与标志性配饰）。"是不是她"从来不只看脸，而这两项从前到不了锚点——`faceMarks` 不在那张清单里，`marks` 还标着 `sheetOnly`（连创作区都不进），于是它们只剩参考图一条路，而小痣在缩略图里根本看不见。两项常为空，空值被 `filter(Boolean)` 滤掉，填了才占位。
- **只做减法**：全量设定表（`characterFaceDesc`）会把表情、姿态、机位一起锁死，交出来的是一张证件照——而参考图恰好也是证件照，两者互相加强。
- **刻意不进**：`style`（媒介归 `medium`）、`identity`（是身份叙事，会把模型引去做角色扮演式构图）、`gender`（见 `part`）。
- 条件 `self && spec`：空锚点不拼；**老角色（无 `fields`）返回空串，不退回全量描述**——那会把治好的病请回来。

### 4.2 `expression`：这一刻的心情，写在脸上

- 来源 [`expressionLine(word)`](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L237)：
  `a <word> expression on the face, not acted out`。
- **排在 `anchor` 之后**：先立住"是谁"，再给"此刻什么样"。
- 条件 `self && frame !== 'close' && moodWord(mood)`，三个护栏各自有理由：
  - `self`：空镜里没有脸；
  - `frame !== 'close'`：特写那一格常常只有一只手、一片布料，请它"在脸上写神情"＝请它把脸画进来，与"一个局部填满画面"正面打架；
  - `moodWord`：**词不合法就什么都不做，绝不猜**（它是模型自由写的、又绕一圈从库里回来）。大小写与首尾空白容忍。
- **一个词，不做词表**：词表一旦出现就要维护，模型一出表外词就出错。
- 后半句 `not acted out` 冲的是具体毛病：只写 `angry`，模型很容易演成一个**动作**（摔东西、吼），而这里要的是**神情**。

### 4.3 `part`：特写时"这一格是那个人身上的局部"

- 来源 [`partLine(gender)`](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L214)：
  `a detail of that same person — <gender, >same age, same skin and same build as the reference, not a generic stand-in`。
- **只在 `frame === 'close'`**：这一档是锚点句**结构上失效**的唯一场景——锚点那七项全是头部与体型，而特写画面里往往没有脸，参考图里那张脸也一起失效，模型就退回它画过最多的那只手。
- **性别单独给、不并进锚点句**：把 `gender` 加进锚点句会改掉这条路上**每一张**图；只补这一档，一个字的代价也不外溢（有单测钉死）。
- 性别为空（老角色）仍保留后半句——它治的是"退回一只通用的手"。

## 五、④ 不可让渡层：`pin` / `frame`

这两层的共同性质：**摄影指导换机位是"整句替换 `camera`"，而这两层不在它的权限里**，所以它们必须自己站得住。

### 5.1 `pin`：这一档不可让渡的那件事

单独成层，**不并进 `camera`**——否则摄影指导替换 `camera` 时会一起换掉：

| 视角 | `pin`（要点） | 换掉的后果 |
| --- | --- | --- |
| `selfie` | 相机在**它自己手上**（臂展/镜子），不是别人拍的 | 画成别人拿相机（用户 2026-10-05 报的） |
| `third` | 手机在**别人手上**，是别人替它拍的 | 退回一张谁拍的都不知道的通用照片 |
| `scene` | 画面里**没有人** | 风景里凭空长出一个人 |

三档共用**一个槽名**，因为它们是同一件事：**这一档不可让渡的那一句**。它不重复 `camera`——`camera` 说"怎么拍"（臂展、前摄、手入画），`pin` 说"谁拿的相机、拿的是什么"。

### 5.2 `frame`：景别硬约束（不可让渡）

- 来源 [`frameLine(self, frame)`](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L582)。**人与空镜两套说法**：空镜里没有"整个人"这回事，写 "the whole person" 就是给"风景里长出一个人"递刀。
- 为什么也单独成层：`FRAMING` 会整句替换 `camera`，而摄影指导写的那句"广角、整个地方都看得见"会把它一起顶掉——它只拿得到一句场景，看不到用户想要的是特写。**所以"推多近"这条不变量单独成层，它换不到，只被告知。**
- 与 `camera` 是**一对**：`camera` 说"怎么拍"，`frame` 说"这一张是哪种景别"。后者必须自己站得住，不能写成"同上"。

| `frame` | 有人 | 空镜 |
| --- | --- | --- |
| `close` | 一个局部填满画面、其余身体出画 | 地方的某一处局部的紧特写 |
| `medium` | 半身（脸与上半身），不是整个人 | 中景：既不推近也不拉远 |
| `full` | 全身（头到脚在框内） | 整个地方一次收入 |

## 六、⑤ 工艺层：`camera` / `lens` / `light` / `env` / `action`

这是唯一**让渡给摄影指导**的一层（前四位），也是"图死板、没有光影"的主要病灶——模板补不上"这个场景具体的光"，只有模型知道。

| 槽 | 出现条件 | 模板给了什么 | 景别能否覆盖 |
| --- | --- | --- | --- |
| `camera` | 总是 | 机位句（自拍/他拍/空镜各一套） | ✔ |
| `lens` | **场景没说镜头** | 景深句 | ✔ |
| `light` | **场景没说光** | 光句（下雨走 `lightWet`） | ✔ |
| `env` | **无条件** | 纵深句 | ✔ |
| `action` | 场景没说动作、**且非特写、且场景不是中文** | "此刻在做什么" | ✘ |

三处容易看走眼的取舍：

- **`env` 无条件补**：环境是**事实**（"在阳台"），纵深是**相机原理**，两者不冲突——场景说了地点照样需要一句"画面要有纵深"（那正是"人和环境融不进去"的药）。做成"没说才补"的结果是几乎每个场景都提过窗/桌/墙，这句永远不出现。
- **`action` 特写不补**：模板那两句是以"画面里有脸"写的（自拍是 `mid-moment, looking into the camera`），请特写"看向镜头"＝请它把眼睛画进来。
- **中文场景也不补**（2026-10-08）：这一层的偏置与其余各层**相反**——漏判不是"落回默认"，是"补一句与场景打架的动作"，而中文动作太自由、那张英文表认不出（见 `ACTION_RE`）。判据是 `hasHan(scene)`。
- **`light` 的下雨分支不走景别覆盖**：光与景别无关——一处光不会因为推近就换个来源，而它照样能把特写照亮。

## 七、⑥ 约束层：`negative`

- 来源 `NEGATIVE` 常量（[chatPhoto.ts L389](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L389)），**垫在最末**。整段被截断时它是最后一个被丢的（有单测钉住 `layers[last][0] === 'negative'`）。
- 它挡三类东西，每类都有明确来路：

| 挡什么 | 词（摘） | 来路 |
| --- | --- | --- |
| 证件照那套默认构图 | `not a character sheet` / `not a passport or ID photo` / `not centered neutral expression` / `not flat lighting` | 参考图与全量清单会互相加强成证件照 |
| **多出来的、长错的**肢体 | `no extra limbs` / `no extra or fused fingers` / `no deformed or duplicated hands` | 用户报的"四肢畸形、缺手少腿" |
| 拼贴 / 接触印相 | `not a collage` / `not a contact sheet` / `no panels` | 我们发的参考图里有两张 2×2 网格，模型会漏成拼版 |

- **刻意不写 `no missing limbs`**：那句会与特写构图（"其余身体出画"）打架——模型读到"不许缺"最省力的解法是**把镜头拉远**，正是这一轮刚修好的毛病。"缺"治在机位句上，不是治在负面词上。
- 不写 `no text`：背景图那一层自己带着，写两遍只是重复。

## 八、三套模板 × 景别：完整文本对照

### 8.1 三套模板的固定句

| 槽 | `selfie` | `third` | `scene` |
| --- | --- | --- | --- |
| `medium` | `photographic, shot on a phone front camera` | `photographic, a casual snapshot taken on a phone by somebody else` | `photographic` |
| `pin` | 相机在自己手上（臂展/镜子） | 手机在别人手上 | 画面里没有人 |
| `camera` | 臂展、前置、**从腰以上**（脸与上半身）、略高机位、轻微广角、手臂入画 | 第三人称、随手拍、偏离中心、全身与手入画、构图随意 | 相机架着/稳持，普通视点 |
| `lens` | `shallow depth of field, background softly out of focus` | `mild background blur, reading as a phone photo rather than a studio portrait` | `shallow depth of field with a soft, readable foreground` |
| `light` | 落在脸上的自然光，从一侧打 | 有明确来源的方向光，一侧脸更亮 | 来自可见光源，扫过场景 |
| `lightWet` | 阴天平光 + 湿处反光，脸被它照亮 | 柔和阴天光 + 地上墙上的湿反光，主体被勾边 | 阴天光 + 湿处反光 |
| `env` | 身后那地方读得出来，近得能摸到 | 有纵深：前景遮挡 / 中景主体 / 后面化开 | 前景 / 中景 / 更远处 |
| `action` | `mid-moment, looking into the camera` | `caught mid-movement, unaware of the camera` | 无 |

> 两档"有人"的模板都必须读成**手机拍的**——只是拿手机的人不同（用户 2026-10-05 的原始要求）。他拍那档刻意不写 portrait/写实摄影那类词，免得被推向影棚。

### 8.2 景别覆盖 `FRAMING`（只登记"非缺省"那两档）

缺省档（`selfie → medium`、`third → full`、`scene → medium`）在表里**没有条目**——所以这一位不存在时，每句话都还是原来那句（改动不可能弄坏已经对的东西）。

| 视角 | 景别 | 覆盖哪几个槽 |
| --- | --- | --- |
| `selfie` | `close` | camera / lens / light / env（臂展换成"一只手举近"，三个自拍信号一个不少） |
| `selfie` | `full` | camera / lens / env（**刻意不写"对镜"**——镜子是场景里的东西，没说就不该凭空添） |
| `third` | `medium` | camera（腰以上、手入画、偏离中心） |
| `third` | `close` | camera / lens / light / env |
| `scene` | `close` | camera / lens / env（一个字都不提人） |
| `scene` | `full` | camera / lens / env（一个字都不提人） |

被覆盖的空位遵循同一句纪律：**camera 那两句刻意不再重复"填满画面"**——那是 `frame` 层的活，两句说同一件事只会把提示词撑长。

## 九、两条正交的判定：视角与景别

两者是**正交**的两位（"谁拿的相机" × "离得多近"），但判据是同一套写法：**标签 > 场景文本 > 缺省**。

### 9.1 视角 `shot`（四级，先命中者赢）

1. **标签**说 `selfie:` / `third:` → 就是它（模型对"谁拿的相机"的直接回答）；
2. 场景明写自拍（`isSelfie`：mirror / arm's length / 自拍…）→ 自拍；
3. 场景明写"别人拍的"（`isThirdShot`：taken by / 偷拍…）→ 他拍；
4. 一条证据都没有 → **默认自拍**（2026-10-05 从"默认第三人称"改过来）。

两条纪律：
- **`self=false` 时视角只能是空镜**，由 `self` 定死，**不由任何人推断**——一张"我看到的东西"里长出一个人，比视角选错严重得多（哪怕标签写了 `selfie:`）。
- **第 2 条压过第 3 条**：一句里同时出现两种字眼，多半是模型在描述画面里的**另一个人**；按自拍画错的方向恰是用户能接受的那一侧。
- 词表都**取窄**：只认明确说法，宁可漏判（落回默认）也不误判。

### 9.2 景别 `frame`（四级，先命中者赢）

1. **标签**说 `close:` / `medium:` / `full:` → 就是它；
2. 场景明说（`frameFromScene`）→ 按它（**两边都命中时特写赢**——用户报的毛病是拍得太远）；
3. 一条证据都没有 → **这一档视角的缺省**（`DEFAULT_FRAME`）。

- **缺省值随视角变**，不是一个统一默认：自拍半身、他拍全身、空镜中景——它必须**逐字等于"这一位不存在时"那三句**。
- 词表取窄：`wide` / `detail` 单独出现时意思不明，一律不认；中文靠 `全身(?!心)` 挡掉"全身心投入"。

## 十、只补不覆盖：`missingSlots`

这是"模板不许和场景打架"的**唯一权威**（模板与摄影指导合并都用它）。

守的位只有两位：

| 位 | 判据 | 为什么只这两位 |
| --- | --- | --- |
| `light` | `LIGHT_RE` + `LIGHT_ZH`（光/灯/影子/逆光…） | 场景说过的光再说一句＝自相矛盾 |
| `lens` | `LENS_RE` + `LENS_ZH`（镜头/焦段/景深/虚化…） | 两个焦段凑一张提示词＝打架 |

三条容易看错的地方：

- **没有"环境"位**：环境是事实，纵深是原理（见 §六）。
- **没有"时间/天气"位**：那是事实不是修辞，编一个"黄昏"会和对话矛盾。
  - 唯一例外：`isWet`（已在下雨/下雪）→ 补"湿处反光"，那是**必然推论**，不是新事实。
- **`lens` 的判据里拿掉了 `close-up` / `macro` / `特写`**（2026-10-06）：它们其实是**景别**的词，现归 `frameFromScene` 管——否则场景一写特写，景深那句（正是特写最需要的）反而不补了。

判据取窄的理由：**宁可漏判（以为没写、于是补一句），也不误判**（把 `sunny` 判成写了 sun、把 `lens` 判成提到镜头）。

## 十一、拼装与截断：`composeChatPrompt`

[chatPhoto.ts L873](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L873)：

```ts
export function composeChatPrompt(layers: ChatLayer[]): string {
  return layers
    .map(([, value]) => value)
    .filter(Boolean)          // 空值丢掉，不留空逗号
    .join(', ')
    .slice(0, CHAT_PHOTO_PROMPT_CHARS)   // 6000
}
```

- 截断发生在**最后一步**，砍掉的正好是垫在末尾的负面约束——所以 `CHAT_PHOTO_PROMPT_CHARS` 从 1200 放宽到 **6000**：不产生任何新调用，只是不再让最后那几层被无声吃掉。
- 拼接符号是 `, `，槽名不进最终字符串（`layers` 里的槽名只服务摄影指导的逐位替换）。

## 十二、槽名 = 权限：与摄影指导的接口

`layers` 之所以必须**留到这一层**（而不是直接吐一个字符串），是因为摄影指导要能**逐位替换**。

- 摄影指导能补四位：`DIRECTOR_SLOTS = camera, lens, light, env`；
- **它拿不到**：`medium / scene / anchor / part / pin / frame / action / negative`——结构上（槽名过滤）就没有入口；
- 合并时三条不变量：① 视角改不了；② 景别改不了；③ **场景已覆盖的位不接受覆盖**（判据同样是 `missingSlots`）；
- 没补上或验收不过的位**逐位退回模板**；一位都没解析出来 → 整层当不可用。

详细见 [photoDirector.ts](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/photoDirector.ts)，那是另一个模块。

## 十三、下游：参考图与尺寸（"这一张怎么拍"的另两种表现）

提示词只是"怎么拍"的一半，另一半是**发哪几张参考图**与**用什么尺寸**——因为**参考图是 i2i 这条路上最强的机位来源**，提示词改近了、手上却给一张全身参考，取景照样被拽回去。

### 13.1 参考图顺序

| 情形 | 顺序 |
| --- | --- |
| `shot = 'third'`（未登记景别） | `full, front, closeups` |
| 其余视角（未登记景别） | `front, closeups, full` |
| `frame = 'full'` | `full, front, closeups`（全身像必须打头） |
| `frame = 'close'` | `front, closeups, body`（**全身像出局**、`body` 进来、正面打头） |
| `frame = 'medium'` | 不登记 → 逐字等于"这一位不存在时"的顺序 |

- 上限 `MAX_CHAR_REFS = 4`，实际发出 **3 张**。
- **`detail`（四个头角度）全面退出参考图**（2026-10-08）：五张设定图里**三张是 2×2 网格**（`detail` / `closeups` / `body`），只有两张是单张人像（`front` / `full`）。参考图是 i2i 的"拷贝先验"，给一张网格就多一份把画面排成多格、多人、多手的先验——**畸形的一大来源**。被摘掉的是语义离"随手拍"最远的那张。结果：**非特写档网格 2 → 1、特写档 3 → 2**。
- `body` 从非特写档**移出**：它本来就排第 5、取不到；留着的话 `detail` 一摘它会顺势顶上第 4 位，网格数一张不减。
- 特写摘 `full`：它会把取景往回拽；补 `body`（2×2 手/臂/腿/脚）：这一档画面常没有脸，锚点句失效，它是"这个部位长什么样"的唯一依据。
- `detail` 仍会生成、仍在角色页显示；**创作区那条路**（`charRefSrcs` 不传 order）照旧用它，这里只改了**对话出图挑哪几张**。

### 13.2 尺寸

[`chatPhotoSize`](file:///Users/sunxiaokai/Desktop/project/KImage/src/lib/chatPhoto.ts#L1047)：按 `shotRatio`（`scene → 3:2`，其余 `2:3`）在**去掉 auto** 的显式比例候选里挑最接近一档；一个都没有才退回 `auto`。**绝不挑 auto**——那等于把自己刚做的决定又交出去。

## 十五、上游接缝：这些事实从哪来

`planChatPhoto` 的四个输入，源头都在聊天模型写在回复末尾的标签里（[CHAT_RULES](file:///Users/sunxiaokai/Desktop/project/KImage/server/routes/chat.js#L28-L43)）：

```
[photo:<手机前缀>:<景别前缀>:<场景描述>]  然后  [mood:word]
```

| 输入 | 来源 | 认不出来时 |
| --- | --- | --- |
| `scene` | 标签里的场景描述（收敛成一行、截 400 字） | 空 = 不发图 |
| `self` | 手机前缀 / `me`、`I'm` 代词 / 场景点了角色名 / **身体部位词兜底**（指甲、手腕、肩膀、皮肤…） | `no-self:` 明确挡在前面 |
| `shot` | `selfie:` / `third:` / `self:`（空） | 客户端按 §9.1 四级判 |
