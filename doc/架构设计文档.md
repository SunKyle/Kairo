## 1. 架构上下文

### 1.1 产品定位

**本地优先的超拟人对话工作台**：用户在自己机器上造角色并与之对话。界面是工具，不是营销页；没有账号、没有云存储，API Key 只在本机。

### 1.2 关键约束

| 约束 | 内容 |
| --- | --- |
| C1 | **无账号、无云存储**：全部数据留在浏览器（IndexedDB + localStorage） |
| C2 | **密钥不出本机**：API Key 只存本机，随请求带给本地代理 |
| C3 | **隐私即卖点**：对话 / 作品 / 密钥不出浏览器是产品承诺，不是实现细节 |
| C4 | **单用户、本地运行**：典型部署是 dev server 或单机 `node server`；Vercel 是可选旁路 |
| C5 | **多厂商归一**：对话 / 识图 / 朗读 / 出图来自多家，需统一成一套接口 |
| C6 | **没有可信后台时钟**：页面关闭后没有任何东西能替角色「主动开口」（2026-10-19 据此砍掉主动联系与虚拟生活） |

### 1.3 非目标

多人协作、跨设备同步、SaaS 多租户、服务端持久化、用户体系；独立生图工作台 / 自由画布 / 提示词库（已从 KImage 裁剪掉）。

## 2. 架构决策（ADR）

每条格式：决策 / 理由 / 后果。

**AD1 — 后端只做「翻译 + 归一化」代理，不持有状态与密钥**
理由：C1–C3 要求服务端不可见用户数据；代理只转发、做 SSRF 防护、错误中文化。备选 BFF 缓存 / 账号体系直接违背 C1/C2。后果：厂商能力差异必须前置到前端能力表（`src/api.ts` 的 `getProvider` / `inferVendor` / `allowedSizes` / `pickActiveByKind`）。

**AD2 — 纯 SPA + 自建 hash 路由 + composables，不用 vue-router / Pinia**
理由：页面虽已增至 6 个，但路由形态简单、状态天然按域切分；引库的体积与心智成本仍不划算。后果：自管 `src/lib/router.ts`、`nav.ts` 与 16 个 composable；换来零额外依赖与完全可控。应用内导航一律 `replaceState`（S-23 已知取舍：浏览器后退直接退出站点，不做站内回退）。

**AD3 — 数据分层：localStorage 存目录，IndexedDB 存字节**
理由：目录条目小、需同步随机读；图片 / 音频体积大、需配额与 Blob 堆外存储。后果：双写一致性、迁移只升不降、死连接重试等工程债落在 `src/lib/idb.ts`。

**AD4 — 厂商能力表前置到前端**
理由与后果同 AD1：能力表是单一事实源，前端渲染（扩展参数、尺寸枚举）与后端分流共用它。

**AD5 — 流式用 NDJSON 而非 SSE**
理由：`{delta}` / `{done}` / `{error}` 结构化帧便于增量写回响应式消息，配 `X-Accel-Buffering: no` 处理代理缓冲。后果：前端自行维护半行缓冲；服务端把上游 `data:` 帧重打包。

**AD6 — 单用户本地优先的信任边界（不挂 CORS、无鉴权）**
理由：前后端同源（本地走 Vite 代理），挂 CORS 反而把代理借给任意网站。后果：一旦公网部署即成为无鉴权开放代理（S-1），必须由部署层显式守护。

**AD7 — 安全三件套：SSRF 防护 + 错误中文化 + 静默超时 / 有限重试**
实现：`server/core.js` 的 `assertSafeTarget` / `isBlockedAddress` / `safeFetch`（含重定向逐跳二次校验）、`CONNECT_HINTS` / `looksLikeHtml` / `htmlTitle`、`UPSTREAM_TIMEOUT_MS`、仅连接层异常才重试。

**AD8 — 一条回复在落盘时扇成多条消息（说 / 想 / 做）**
理由：心理层次需要消息级状态，而不是行内标签；`ChatMessage.layer` 是 additive 可选字段，老数据零迁移。实现：`useChatFlow` 用 `parseLayers` 把末尾回复拆成 say/think/act 多条；`showThink` / `showAct` 只管展示，`sceneMode` 管产出，`keepInSummary` 管记忆。后果：`regenerateChat` 需要删掉末尾整段连续 assistant，而不是一条。

**AD9 — 长期记忆、心情、关系按「对话域 / 角色域」分开存**
记忆简报（`chat_summaries`）与心情（`char_moods`）属于「这一段对话此刻的状态」，换一段对话不该跟着走；关系（`relationship`）属于角色，跨对话延续。注入时各自成段：`memorySection` / `memoryBriefSection` / `moodContext` / `relationshipSection` / `guidanceSection`，任一为空就整段不出现。

## 3. 系统结构

```
┌─────────────────────────────────────────────────────────────┐
│  浏览器（用户本机）                                            │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Vue 3 SPA（纯前端，无账号）                              │  │
│  │  pages: Home / Chat / Characters / Memory / History / Settings │
│  │  composables(16, 按域持状态)                             │  │
│  │  lib: 能力表 / idb / router / nav / ui / chatPhoto /      │  │
│  │       messageLayers / memory / relationship / typing …    │  │
│  │  数据: localStorage(kimage.*) + IndexedDB(kimage.db v14) │  │
│  └───────────────────────────┬───────────────────────────┘  │
└──────────────────────────────┼──────────────────────────────┘
                                │ 同源 /api（本地 Vite 代理）
                                ▼
┌─────────────────────────────────────────────────────────────┐
│  Express 代理（server/，68 行装配 + routes/ 五模块）          │
│  generate │ enhance │ chat(NDJSON) │ tts │ test               │
│  chat*.js: 规则 / 优先级 / 记忆 / 心情 / 分层 / 发图 / 标签     │
│  core.js: SSRF 防护 / 代理 / 超时 / 错误中文化 / 内存限流      │
│  ⚠ 无服务端密钥、无鉴权（本地优先信任边界，见 AD6/S-1）         │
└──────────────────────────────┬──────────────────────────────┘
                                │ 带用户 BaseURL+Key
                                ▼
              ┌──────────────────────────────────────┐
              │ 上游厂商（OpenAI / Ark / DashScope /  │
              │ Gemini / custom / 文本·识图·语音厂商） │
              └──────────────────────────────────────┘
```

### 3.1 前端

**页面**：`HomePage`（落地址 `#/`，角色展示 + 最近对话）、`ChatPage`（对话与沉浸态）、`CharacterPage`（创建向导 / 列表 / 详情）、`MemoryPage`（记忆中心主从双栏）、`HistoryPage`（生成归档）、`SettingsPage`（外观 / 互动 / 接口配置的分区容器）。

**路由形态**：`#/`、`#/chat/:id`、`#/chars/:id`、`#/memory`、`#/history/:id`、`#/history/by/:charId`、`#/settings`。`RouteState` 的 `id` 与 `byChar` 是两件事，不能混用（两种 id 都是 `uid()`）。

**composables（16）**：`useAppShell`（外壳与路由分发）/ `useConfigs` / `useChat` / `useChatFlow`（编排，最大）/ `useChatStream` / `useGeneration` / `useHistory` / `useCharacters` / `useMemories` / `useRelationship` / `useFeedback` / `useCharacter{Draft,Wizard,Detail,List,Voice}`。子组件只做展示。

**lib 关键模块**：`api.ts`（能力表 + 后端调用 + 导入导出 + IDB 门面）、`idb.ts`（存储与迁移）、`chatPhoto` / `photoDirector`（发图）、`messageLayers`（说/想/做）、`memory` / `relationship` / `prefs`（长期状态）、`typing`（分拍节奏）、`chatSplit` / `chatDraft` / `moodDisplay`（表达细节）、`router` / `nav`（导航）。

**体量**：`CharacterPage` 约 4045 行、`ChatPage` 约 3256 行、`App.vue` 约 2302 行、`src/api.ts` 约 2728 行。状态已抽 composable，组件主要是模板 + 样式；拆解仍是 P3 工程债（T21）。

### 3.2 后端

`server/index.js` 只做装配 + `express.static` + SPA fallback；五条路由：

| 路由 | 职责 |
| --- | --- |
| `POST /api/generate` | 文生图 / 图生图；角色设定图、对话发图、背景图都走它 |
| `POST /api/enhance` | 改写 / 拆角色 / 识图 / 记忆摘要 |
| `POST /api/chat` | 角色对话，NDJSON 流式 |
| `POST /api/tts` | 火山语音合成（preset / describe / clone） |
| `POST /api/test` | 连通性测试 |

对话侧拆成一组纯函数模块：`chatTags`（标签剪取注册表）/ `chatLayers`（说想做）/ `chatMemory`（简报与截断）/ `chatMood` / `chatPhoto` / `chatPriority` / `chatGuidance` / `chatTime` / `relationship`。`check:server` 只检查未定义名（TS2304/2552），纯 JS 模块的导出靠 `.d.ts` 声明。

### 3.3 数据

**localStorage（`kimage.*`）**：`apiConfigs` + 五类 `apiActive*`、`characters`、`theme`、`immersive`、`interactionPrefs`、`sceneMode`、`showThink` / `showAct`、`collections`、`memoryMigrated`、`sync`。旧键 `kimage.apiConfig` 保留迁移逻辑。

**IndexedDB（`kimage.db` v14，10 张表）**：`history` / `chars` / `chat_messages` / `chat_summaries` / `chat_images` / `chat_backdrops` / `char_moods` / `memories` / `tts_cache` / `voice_samples`。

`DB_VERSION` 只加不减（号比库里小会 `VersionError`，调用方 catch 成「读不出来」= 用户以为数据没了）。v14 新增 `memories`；`covers` 表已随提示词库整链删除（S-5）。

**存储治理**：`ensurePersisted()` 申请持久化配额；写入即体检，占用超 80% 水位清最旧 30%（`MIN_KEEP=20`，拿不到配额时 `HARD_LIMIT=500`），作品集记录免清理；体检有 30s / 20 条节流，连接缓存 + `retryOnDeadConnection`。`planPrune` 已保护 marked（原 P0 已闭合）。

## 4. 关键链路

| 链路 | 设计依据 |
| --- | --- |
| 角色（正脸为锚 + 默认五类设定图 + 其他设定图） | 角色创建与形象 / 角色出图 |
| 对话（NDJSON 流式 + 记忆 + 心情 + 关系 + 朗读） | 角色对话 |
| 说 / 想 / 做与场景模式 | 对话体验 §6 |
| 对话发图（六层拼装） | 角色出图 |
| 沉浸式对话（全屏背景） | 对话体验 |
| System Prompt 装配 | System-Prompt |
| API 配置（五类共用一份列表） | API配置管理设计 |
| 设计 token | 设计系统 + `src/style.css` 的 `:root` |

**一次对话的请求组装**（细节见 S01）：`chatSystemPrompt` 先给信息优先级段，再依次拼人格、相处偏好、关系、记忆简报、记忆条目、心情、分层规则、发图协议（`canDraw` 才注入）。响应以 NDJSON 回流，前端 `Pacer` 按标点分拍逐字显示；终帧解析标签、落盘、扇成多条消息，再异步触发摘要 / 心情 / 关系评估 / 记忆抽取。四类「没说完」：用户 Stop（`stopped`）、上游报错（`failure`）、撞 `max_tokens`（`truncated`）、静默超时。

**并发控制**：四套独立 AbortController（设定图 / 对话流 / 提示词改写 / 发图与背景图，后者登记在 `imageJobs`）；其余是 per-key 忙等守卫（`chatBusy` / `chatPhotoBusy` / `backdropBusy` / `chatSummarizing`），没有全局并发闸。

## 5. 架构评审

### 5.1 强项

**隐私与安全边界清晰且落地**：无服务端密钥、SSRF（含重定向二次校验）、错误中文化、无多余 CORS。**存储层工程扎实**：迁移只升不降、死连接重试、配额驱动清理且保护 marked、孤儿附图清理、Blob 堆外。**测试与类型健康**：截至 2026-10-20，949 个用例 / 37 文件全过，`vue-tsc` 零报错，CI 跑 typecheck / lint / test / build / 端到端探针 / 性能预算。**关注点分离**：状态在 composables、能力表单点、通用 UI 机制在 `lib/ui.ts`。**设计系统一致**：单强调色、token 单点、语义断点。

### 5.2 待处理风险

| 编号 | 风险 | 严重度 | 现状 |
| --- | --- | --- | --- |
| S-1 | 公网部署 = 无鉴权开放代理 | 高（条件触发） | `vercel.json` 已把 `/api/*` 指到函数；上线前必须加仅本机 / 共享密钥 / 上游域名白名单 |
| S-2 | 服务端安全三件套零单测 | 中 | SSRF、重定向、`rateLimit` 无回归信号；建议表驱动单测（含 IPv6 与 DNS 重绑定） |
| S-3 | 上游 120s 超时超 Vercel 函数上限 | 中 | `vercel.json` 无 `functions.maxDuration`，线上长回复会在平台侧被先杀 |
| S-4 | 请求体 15MB 超平台约 4.5MB | 中 | 大 PNG 到不了友好 413，用户看到平台错误页；应在前端按平台上限预检 |

**架构级工程债（非阻塞）**：三个巨型组件（T21）、历史页仍一次性读全库且无虚拟滚动（T20）、全库备份缺失（只有单角色 zip，T26）、限流是内存滑窗（Serverless 下非全局配额）、API Key 明文在 localStorage（设置页已明示本地属性，尚无「仅本次会话」选项）。

**历史评审项**：S-5 – S-24 共 20 项已于 2026-10-13 全部修复（死代码、跨标签页一致性、错误兜底、导入导出、出图可取消、端口与文档失实等），原始记录归档在《架构评审报告.md》，不再作为待办。

### 5.3 结论

架构方向正确，本地优先的信任边界、存储层工程、测试与类型健康达到成品级，**无需架构级返工**。剩余缺口集中在公网部署护栏（S-1/S-3/S-4）与服务端安全单测（S-2）；其次是巨型组件与历史页首屏这类按需处理的工程债。

## 6. 本地 Node 与 Vercel Serverless 的差异

| 维度 | 本地（`server/index.js`） | Vercel（`api/index.js`） |
| --- | --- | --- |
| 鉴权 | 无 | 无（= 开放代理，S-1） |
| 上游超时 | 120s（自管） | 受函数执行上限约束，需 `maxDuration`（S-3） |
| 请求体上限 | express 15MB，给友好 413 | 平台约 4.5MB 先行拦截（S-4） |
| 限流 | 单进程内存滑窗有效 | 按实例、冷启清零、非全局 |
| trust proxy | 仅 `ON_SERVERLESS` 开启；本地按 socket 地址 | 取 XFF 第一段（两端口径不可比） |
| 私网目标 | 本地开发默认放行回环 / 内网 | 一律 400（同一配置两种行为） |
| SPA fallback | 仅 `dist/` 存在时托管并兜底 | 平台兜底，函数内 static 分支不可达 |

> 结论：Vercel 只是「能跑」的旁路，不是等价部署形态。真要上线，先完成 §5.2 的 S-1/S-3/S-4，并在文档里固定这套差异。
