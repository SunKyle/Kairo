## 1. 架构上下文（Context & Constraints）

### 1.1 产品定位
**本地优先的超拟人对话工作台**：用户在自己机器上造角色并与之对话；界面是工具而非产品页（无营销页、无首屏 hero）。

### 1.2 关键约束（架构的「重力」）
这些约束决定了一切分层的走向，所有决策都绕着它们转：

| 约束 | 内容 |
| --- | --- |
| C1 | **无账号、无云存储**：全部数据留在浏览器（IndexedDB + localStorage） |
| C2 | **密钥不出本机**：API Key 只存本机，随请求带给后端代理 |
| C3 | **隐私即卖点**：对话 / 作品 / 密钥不出浏览器是产品承诺，不是实现细节 |
| C4 | **单用户、本地运行**：典型部署是 dev server 或单机 `node server`（Vercel 是可选旁路） |
| C5 | **多厂商归一**：对话 / 识图 / 朗读 / 出图来自多家，需统一成一套接口 |

### 1.3 非目标（Explicitly out of scope）
- 多人协作、跨设备同步、SaaS 多租户。
- 服务端持久化与用户体系。
- 独立生图工作台 / 自由画布 / 提示词库（已从 KImage 裁剪掉——见 R1）。

## 2. 架构决策记录（ADR 摘要）

每条格式：决策 / 理由 / 备选 / 后果。

**AD1 — 后端只做「翻译 + 归一化」代理，不持有状态与密钥**
- 理由：C1–C3 要求服务端不可见用户数据；代理只转发、加 SSRF 防护、做错误中文化。
- 备选：BFF 带服务端缓存 / 账号 → 直接违背 C1 / C2。
- 后果：上游厂商差异（OpenAI / Ark / DashScope / Gemini / custom）的适配逻辑**必须前置到前端能力表**（`src/api.ts`）。

**AD2 — 前端纯 SPA + 自建 hash 路由 + composables（不用 vue-router / Pinia）**
- 理由：页面仅 4 个、状态已按域抽到 11 个 composable；引库收益低、体积与心智成本不划算。
- 后果：路由 / 状态自管，需维护 `src/lib/router.ts`、`nav.ts` 与 composables；换来零额外依赖与完全可控。

**AD3 — 数据分层：localStorage 存目录、IndexedDB 存字节**
- 理由：目录条目小、需同步随机读；图片 / 音频体积大、需配额与 Blob 堆外存储。
- 后果：双写一致性、迁移只升不降（`DB_VERSION` 只能加）、死连接重试等工程债落到 `src/lib/idb.ts`。

**AD4 — 厂商能力表前置到前端 `api.ts`**（`getProvider` / `inferVendor` / `allowedSizes` / `pickActiveByKind`）
- 理由：见 AD1 后果；能力差异是前端渲染（发哪些扩展参数、尺寸枚举）与后端分流的共同依据。
- 后果：能力表成为「单一事实源」，改动厂商行为只改一处。

**AD5 — 流式用 NDJSON 而非 SSE**
- 理由：`{delta}` / `{done}` / `{error}` 结构化帧便于前端增量写回响应式消息，配 `X-Accel-Buffering: no` 处理代理缓冲。
- 后果：前端需自行维护半行缓冲（流解析逻辑）。

**AD6 — 单用户本地优先的信任边界（不挂 CORS、无鉴权）**
- 理由：前端与 `/api` 同源（本地走 Vite 代理），挂 CORS 反而把代理借给任意网站；无用户体系则无鉴权。
- 后果：一旦公网部署即变成**无鉴权的开放代理**（见 R2）——这是本地优先设计的固有边界，需在部署层显式守护。

**AD7 — 安全三件套：SSRF 防护 + 错误中文化 + 静默超时 / 有限重试**
- 实现：`server/core.js` 的 `assertSafeTarget` / `isBlockedAddress` / `safeFetch`（含重定向二次校验）、`CONNECT_HINTS` / `looksLikeHtml` / `htmlTitle`、`UPSTREAM_TIMEOUT_MS`、仅连接层异常才重试。
- 理由：代理会去连用户填的任意 Base URL，是 SSRF 高发面；错误中文化是「工具感」的一部分。

## 3. 系统结构（Container / Component）

```
┌─────────────────────────────────────────────────────────────┐
│  浏览器（用户本机）                                            │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  Vue 3 SPA（纯前端，无账号）                              │  │
│  │  pages(Chat/Chars/History/Settings)                      │  │
│  │  composables(11, 按域持状态)                             │  │
│  │  lib(能力表 / idb / router / nav / ui / chatPhoto…)     │  │
│  │  数据: localStorage(kimage.*) + IndexedDB(kimage.db v13) │  │
│  └───────────────────────────┬───────────────────────────┘  │
└──────────────────────────────┼──────────────────────────────┘
                                │ 同源 /api（本地 Vite 代理）
                                ▼
┌─────────────────────────────────────────────────────────────┐
│  Express 代理（server/，68 行装配 + routes/ 五模块）          │
│  generate │ enhance │ chat(NDJSON) │ tts │ test               │
│  core.js: SSRF 防护 / 代理 / 超时 / 错误中文化 / 内存限流      │
│  ⚠ 无服务端密钥、无鉴权（本地优先信任边界，见 AD6/R2）         │
└──────────────────────────────┬──────────────────────────────┘
                                │ 带用户 BaseURL+Key
                                ▼
              ┌──────────────────────────────────────┐
              │ 上游厂商（OpenAI / Ark / DashScope /  │
              │ Gemini / custom / 文本·识图·语音厂商） │
              └──────────────────────────────────────┘
```

**前端域**
- `pages`：ChatPage / CharacterPage / HistoryPage / SettingsPage（仅展示，状态在 composable）。
- `composables/`：11 个，按域持有业务状态（useConfigs / useChat / useChatFlow / useGeneration / useCharacter* …）。
- `lib/`：能力表门控、idb 存储门面、router、nav、ui 通用机制、chatPhoto / photoDirector、chatMood、providers 等。
- `components/`：通用小组件（ImagePreview / UndoToast / notice / 角色悬停卡）。

**后端域（`server/`）**
- `index.js`：68 行装配 + static + SPA fallback + 兜底错误。
- `routes/`：generate / enhance / chat / tts / test，各自注册。
- `core.js`：安全与网络基础设施（SSRF、代理、超时、错误翻译、限流）。

**数据域**
- localStorage `kimage.*`：配置列表、五类 `activeId`、角色目录、主题、沉浸偏好。
- IndexedDB `kimage.db` v13：history / chars / chat_messages / chat_images / chat_summaries / tts_cache / voice_samples / chat_backdrops / char_moods（covers 见 R1）。

## 5. 架构评审（Review）

### 5.1 强项（值得保持）
- **S1 隐私 / 安全边界清晰且落地**：无服务端密钥、SSRF（含重定向二次校验）、错误中文化、无 CORS 多余暴露。
- **S2 存储层工程极为扎实**：`idb.ts` 的迁移只升不降、死连接 `retryOnDeadConnection`、配额驱动 `pruneHistory` 且**已保护 marked**（见 §6 修正 P0#1）、孤儿附图 `pruneChatImages`、节流 `shouldCheckStorage`、Blob 堆外——这些是很多生产项目都做不好的点。
- **S3 测试与类型健康**：624 用例全过、`vue-tsc` 零报错（现状文档 §9 实测）。`planPrune` / `referencedChatImages` 等「决定删什么」的逻辑抽成纯函数可单测，是正确的工程做法。
- **S4 关注点分离到位**：状态抽 composables，能力表单点 `api.ts`，通用 UI 机制 `lib/ui.ts`。
- **S5 设计系统一致性**：单强调色、token 单点 `:root`、语义断点——与产品「克制 · Editorial」性格自洽。

### 5.2 风险与问题（按严重度）

**P0 — 数据安全 / 一致性**
- **R1 `covers` / `PromptItem` 与现状文档自相矛盾（高）。** 现状文档 §2 / §4.2 称「提示词库页面已移除，`covers` 表可能已弃用」，但源码仍在实现它：`api.ts` 的 `getAllCovers` / `putCovers` / `coversOf(list: PromptItem[])` 与 `App.vue` 仍引用。需二选一：① 功能实际未删 → 补回文档、确认是导出兼容路径；② 是死代码 → 清理 `covers` store 与 `PromptItem` 相关分支，避免误导与无谓存储。
- **R2 公网部署 = 无鉴权开放代理（高，条件触发）。** `vercel.json` 已配置 `/api/*` → `api/index.js`，即部署即公网。AD6 的「无鉴权」在本地成立，公网即风险：任意网站可借你的代理 + 你的密钥访问任意 Base URL（SSRF 防护只挡私网、不挡公网外部）。需在部署层加：默认仅本机、或共享密钥、或上游域名白名单。

**P1 — 正确性与一致性**
- **R3 `sourceRef` 注释引用不存在的「作品提升」功能（中）。** `types.ts:486` 注释「也含从作品提升为参考的那一张」，但全仓无此功能。应改为只描述「第一步上传的底图」。
- **R4 粉紫渐变 token 悬空（中，已定位到具体 token）。** 复审更正：`--ai-halo`（金）**并未悬空**——它是「机器在跑」的呼吸光，见 `src/style.css:48/157` 定义、`.halo-breathe`（348–350）消费。真正零载体的是粉紫 `--ai-from`/`--ai-to`（`style.css:41–42/154–155` 仅有定义，全仓无 `var(--ai-from|--ai-to)`）——原「只标画布 AI 入口」的那套渐变随画布移除而死，应删除或重指派语义。
- **R5 文档引用用「文件 + 行号」（中）。** 行号随代码漂移，应改为符号名（函数 / 常量）。

**P2 — 工程健康**
- **R6 无 CI / 无 README / 无 lint（中）。** 现状 §9 已列；README 至少需「怎么跑、数据在哪、密钥在哪、本地优先信任边界」。CI 跑 `typecheck + test + build` 即可获得高收益。
- **R7 超大页面组件（低–中）。** CharacterPage(~148KB) / ChatPage(~143KB) / SettingsPage(~66KB) / HistoryPage(~48KB)。状态已抽 composables，组件主要是模板 + 样式，风险可控；可在文档 / CI 之后按需拆。

**P3 — 安全部署细化**
- **R8 限流为内存滑窗（中，Serverless 下 ≈ 无全局配额）。** 防滥用需外部存储。
- **R9 API Key 明文 localStorage（低–中）。** 设置页应明说「本地优先 = Key 在浏览器」，并可选「仅本次会话保存」。

**P4 — 体验**
- R10 界面英文 / 注释中文不一致；大历史库无虚拟滚动（现状 §10#13，非阻塞）。

### 5.3 评审结论（Verdict）
- 架构方向**正确**，本地优先的信任边界、存储层工程、测试 / 类型健康都达到成品级，可作为「本地优先 AI 应用」的参考范本。
- 主要缺口集中在三层：**(a) 文档与代码一致性**（R1 / R3 / R4 / R5）、**(b) 公网部署安全**（R2，条件触发但后果严重）、**(c) 工程基建**（R6）。
- **不建议做架构级返工**；建议以「文档对齐 + 部署护栏 + 补 README/CI」为主线的增量改进。
