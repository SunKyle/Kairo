# 角色创建流程设计

> 本文总结 KImage 中「角色（Character）」从新建到落库、出图的完整设计。
> 相关实现集中在这几处：
> - [CharacterPage.vue](../src/components/CharacterPage.vue) —— 向导、列表、详情、查看器（只管展示与编排）
> - [App.vue](../src/App.vue) —— 落库、出图、存储、跳转（字节与状态都在主界面）
> - [api.ts](../src/api.ts) —— 五张视图定义、AI 起稿、识图、导入导出
> - [types.ts](../src/types.ts) —— 数据结构
> - [server/charSpec.js](../server/charSpec.js) —— **那份行定义**：字段、顺序、标签、必填、枚举的唯一来源
> - [server/enhancePrompts.js](../server/enhancePrompts.js) —— 起稿 / 识图的提示词正文
> - [server/index.js](../server/index.js) —— 起稿 / 识图的端点与解析标签

## 1. 核心概念

一个角色 = **一组设定图 + 一段结构化设定 + 名字 + 一张参考底图**。

设计上最要紧的一条：**参考图管"形状"，设定管"语义"**，两者一起注入才谈得上跨图一致。

- **正脸（Front）是唯一的锚**：五张设定图里，正脸是主视图，其余四张一律以正脸为参考图生成 —— 这是"跨图保持同一张脸"的唯一办法。
- **主视图只有一个：正面。** 没有"选主视图"这件事，只有"正面在不在"（有无即状态，不再存 `refKind`）。
- **两个输入源分离**：
  - `ref` = 封面 / 头像。正脸生成成功后它就是正脸本身。
  - `sourceRef` = 第一步上传的底图。它服务两处：生成正脸时的参考图；其余四张与正脸一起送出的第二张参考图。正脸生成后 `ref` 被换成正脸，底图靠 `sourceRef` 保住。

### 数据模型（[types.ts](../src/types.ts#L184-L265)）

| 类型 | 作用 |
| --- | --- |
| `Character` | 角色主记录：`id / name / createdAt / fields / desc / ref / sourceRef / refKind / views` |
| `CharacterFields` | 结构化设定，16 项：`style, gender, identity, face, height, build, muscle, posture, hair, brows, eyes, noseMouth, facialHair, faceMarks, outfit, marks` |
| `CharacterViewKind` | `'front' \| 'detail' \| 'full' \| 'closeups' \| 'expression'` |
| `CharacterView` | 单张设定图：`{ kind, data: Blob }` |
| `CharacterDraft` | 一次 AI 起稿结果：`{ name, fields }`（名字不属于 `CharacterFields`，不进提示词） |
| `CharacterStat` | 用量（生成次数 / 最后使用），**从历史记录派生，不落盘** |
| `CharacterWork` | 该角色名下的一件作品（历史里带 `characterId` 的记录中的一张图），同样派生 |

**字段分两组** —— 键、顺序、必填、枚举都只有一份来源：[server/charSpec.js](../server/charSpec.js)
那份行定义（服务端拼起稿提示词用的也是它，前端 [api.ts](../src/api.ts) 与
[lib/characterSpec.ts](../src/lib/characterSpec.ts) 从它取键序与选项）：
- 除 `outfit` / `marks` 之外的 14 项 = 面貌与身材特征 → 会跟着**每一张成品**走（`characterFaceDesc`），其中 `height / build / muscle / posture` 是后补的"身材那四行"；
- `outfit` / `marks` = 只喂给设定图，不该进普通创作提示词（行定义里的 `sheetOnly`）。

> 在这之前这几份清单是**各写各的**：服务端两段提示词里各一份行清单与一份必填枚举、
> 前端一份字段顺序、一份标签对照表。加一栏要同时改六处，而漏掉任何一处都不报错 ——
> 表现只是"模型少回一行，那个字段静静地空着"。
> 现在改一栏只有两处要跟手：行定义 + `types.ts` 的接口（后者的键由单测对着行定义比）。

**存储分工**：目录（`Character[]`）是轻量 JSON，放 localStorage；图是 Blob，按角色 id 存 IndexedDB（`putCharView` / `getCharViews`）。

## 2. 创建流程总览

创建是一条**独立流程**，以漂浮卡（模态）形式盖在角色页之上，关掉即回到原样。三步摊成一张卡：**步骤条在头上，内容在中间，进退在脚下**；没做到的那一步在条上是锁的，点不动 —— 顺序靠结构说明，不靠报错。

```
Basics ──► Main view ──► Other views ──► 详情页
（填设定     （生成正脸，      （生成其余       （落地页）
 /传参考图）   其余四张的锚）     四张 2×2）
```

步骤条三步（[CharacterPage.vue](../src/components/CharacterPage.vue#L613-L617)）：

| 步 | 标签 | 图标 | 意图 |
| --- | --- | --- | --- |
| 1 | Basics | `PhTextAa` | 填名字、性别与那份设定（收的全是字） |
| 2 | Main view | `PhUser` | 一张正脸，后面每张图都从它长出来 |
| 3 | Other views | `PhSquaresFour` | 其余四张视图，一条 2×2 格子 |

**步骤解锁规则**（`stepUnlocked` / `stepDone`）：
- 第 2 步需要 `wizardId`（第 1 步已存下）；
- 第 3 步需要正脸已存在（`wizardFront`）；
- 做完的步骤在条上打勾（`PhCheck`），与"正在这一步"区分；两段连接线只在前一步做完时点亮。

> ⚠️ 这条规则有一条副作用，2026-10-03 补了一个入口来收：第 2 步的解锁条件是 `wizardId`，
> 而它**只在新建流程里**（第 1 步存完）才会有值 —— 详情页那枚 `Edit` 走的是 `editingId`，
> `wizardId` 始终是空的。于是"改一条已有角色的嗓子"这条路**根本进不去**：
> 建完就再也改不了（详情页那块 Voice 只给"听"，不给"改"）。
> 现在详情页 Voice 那一块多了一枚 **Change voice**（`startVoiceEdit`）：
> 它把 `wizardId` 认成这条角色、步数直接拨到 2，所以既进得去、也存得下
> （存的仍是 `saveFromVoiceStep`，只是存完回详情而不是接着去出图）。
> `Edit` 那条路保持原样 —— 只改设定的那一轮不该被迫多走两步。

**角色在第 1 步保存时落库** —— 第 2、3 步都要 `charId` 才能出图。所以第 1 步存下之后转成**只读摘要**（这一页没有"改角色"，留着可编辑表单只会让人再存一个副本）。`submit()` 只发意图，存完由父组件回调 `onSaved(id)` 推进到第 2 步 —— 因为 `save` 是异步的，现在改步数会在角色还没进列表时先跳过去。

**右栏常驻"这个角色是什么"**（`wz-rail`）：三步共用。有已保存角色就读它，没有（第 1 步还没存）就读手上草稿。意义在于第 3 步要判断"这四张是不是同一个人"，而那一屏只有四张图 —— 右栏把设定和主视图缩略摆在旁边当比对基准。第 1 步同样有用：一句话起稿会一次填进所有栏位，右栏是一份"它到底读出了什么"的连读清单。

## 3. 第 1 步：Basics

模板： [CharacterPage.vue#L1156-L1426](../src/components/CharacterPage.vue#L1156-L1426)

### 3.1 起稿块（仅新建态）

整张卡上唯一享受"区域"待遇的一块，自带标题与引导语。

- 标题：**"Who are you creating?"**（问的是人，不是工具）；
- 引导语：一句话就能开工，细节只是起点 —— 不描述机器在背后做什么；
- 输入是一个 `textarea`（收的是"一个人的样子"而不是一个词），两行起步、随内容长高（`vGrow`）、6 行封顶后内部滚；
- **回车起稿，Shift+回车换行**（`onIdeaEnter`，带 `isComposing` / `keyCode 229` 输入法保护）；
- 起稿中整块走金色呼吸光晕（`halo-breathe`），因为 `textarea` 是替换元素放不了 `::after`，光晕挂在块上；
- 按钮文案随状态变化：`Draft the spec` → `Drafting…` → `Draft again`（已有内容时）。

### 3.2 上传参考图 → 识图

- 参考图放在表单**最后**（比文字更能定形状，但可选）；
- 空态与有图态**占同样高度**，挑完图整块不跳动；
- 上传后**自动跑一次识图**（`onPickRef` → `draftFromImage`），因为"传张图上去"的意图本来就是照着它填；按钮留着是为了重读 / 改配置后重试；
- **编辑态不自动识图**：用户是来换参考图的，不是让模型把他校对过的那份设定重写一遍；
- 送模型的是**压到最长边 1024 的 JPEG**（`visionCopy`，q=0.85，先铺白底防透明 PNG 变黑）—— 上传原图可能几十 MB，而请求体上限 15MB，原样发会 413；存档用的仍是原图；
- 参考图上限 `MAX_REF_BYTES = 32MB`，且必须 `image/*`；
- 编辑态参考图**只能换、不能删**（底图是其余四张的参考资料，删掉那些图就失去"原本是什么"这一半信息）。

### 3.3 表单字段

| 组 | 标题 | 提示 | 字段 |
| --- | --- | --- | --- |
| Basics | Basics | 卡片上的名字 + 模型用来定脸的那个词 + 用哪种媒介画 | `Name`*、`Gender`*、`Style` |
| Spec | Spec | The face travels with every image you generate. | `identity, face, hair, brows, eyes, noseMouth, facialHair, faceMarks` |
| Body | Body | Height, build, muscle and posture — also kept the same everywhere. | `height, build, muscle, posture` |
| Reference sheet only | Reference sheet only | Shaped into the reference sheet only — never merged into your other prompts. | `outfit, marks` + 自由 `Extra details` |
| Personality | Personality | Who they are and how they talk. Used in Chat only | `language, traits, voice, address, boundaries, samples` |

- **仅两条必填**：姓名（给卡片当标题）与性别（给模型定脸的第一道条件）。其余一律可留空 —— 所以"不标星号"已经说完了"可选"，不必反过来挂 `Optional`；
- 必填靠字段名后一枚**墨色星号**（`aria-hidden`），语义由控件的 `aria-required` 说，不用装饰表达；
- **性别与风格都是下拉，不是一个可以随便写的输入框**：模型只认 `female` / `male` 与那几个媒介词（枚举就在 `charSpec` 的行定义里），留自由文字等于又把这件事交回给模型猜；模型偶尔写出枚举之外的值（如 `non-binary`、`watercolor`）时，把它当成额外一项显示出来（`genderOptions` / `styleOptions`）—— 吞掉它才是错的：界面上看不见，提示词里却还带着；
  - 为什么是下拉而不是一排胶囊（原来那样）：一排胶囊要先画一条灰槽、把选中的那枚涂成实心墨块，两个词的选项于是占掉一整条 46px 高的横档，风格那六枚更是铺成 470px 宽的一整块灰板 —— 而这一步其余每一行都只是"一个灰标签 + 一行字"。这五栏里真正要读的是**值**，不是控件本身；收成一个值的大小，行才回到同一套读法。它同时把"值"这一列留给了文字：`.ed-input` 那套无框无底照旧，右边一枚小箭头说明这里点得开（`.wz-select`）；
- **风格那一栏的第一项是 `Auto`，而且默认就是它**：对应的值是**空串**，空值会被 `filter(Boolean)` 滤掉，于是风格由参考图说了算。有底图时再写死一个媒介词，就是让文字去跟图打架；
- **`Body` 是补上的一组**：那张 `Full body` 视图的立意是"交代体型与服装轮廓"，而在此之前没有任何一项描述身材 —— 身材每张都是模型现编的，是跨图一致漏得最大的一处。这一组四行（`height / build / muscle / posture`）刻意**没有合成一行**：身高、骨架、肌肉、体态会各自独立漂移，写在一句话里模型会把它们平均成"中等身材"，而这一层的全部意义正是别让它平均。`muscle` 与 `posture` 允许留空（与 `Face marks` 同一条理由）—— 它们常常在这张图里根本看不见，硬要一个值等于逼模型去编；
- 规格字段是**自增高 `textarea`**：字段值上限 12 个词 / 约 70 字符，两列下每栏仅约 338px，`input` 会把边界值截在视野外；封顶三行再多内部滚。

> **`Extra details`（自由补充）**：它落在 `Reference sheet only` 那一组里，是整张表单唯一一处能写"固定栏位装不下的要求"的地方 —— 例如"别画成典型的 AI 脸"。它对应的值仍是 `Character.desc`，只被拼进**设定图**的提示词（`characterDesc`），不进普通创作提示词（`characterFaceDesc` 不收它）。组提示从 "never merged into your prompts" 改成 "never merged into your **other** prompts"，就是为了不再让人误读成"这一组填了也不起作用"。

### 3.4 AI 起稿的两条路（共用回填规则）

两条路拿到的是同一份「名字 + 结构化设定」，回填规矩一模一样（`applyDraft`）：

| | 文字起稿 | 识图 |
| --- | --- | --- |
| 函数 | `draftCharacterFields` | `draftCharacterFromImage` |
| 接口 | `/api/enhance` `mode: 'character'` | `mode: 'vision'` |
| 温度 | 0.7（具体又不重复） | 0.4（照图写，放开就会编） |
| 配置 | 文本模型 | 识图模型（能画图的模型未必会看图） |

- **二十二行固定格式**（`Name` + 16 项设定 + 5 项人格），不用 JSON —— 少一整类"围栏/多余解释"的解析坑，人也能直接读懂。行清单、行数、"必须始终有值"那句枚举都由 [server/charSpec.js](../server/charSpec.js) 生成，两段提示词只留各自独有的规则；
- **`character` 允许把没提到的编具体**（模糊才是漂移的源头），但 `Face marks` / `Marks` 只在原句真提到时才写，否则默认给每个人添一道疤是错的；`Language` 同理 —— 只有原句真说了语言才写，**不许从名字、国籍或长相推**；
- **`vision` 只写看得见的**：凭空添疤、加义体等于把用户上传的人改成另一个人；
- 回填后**给模型填的每一栏打一枚小点**（`aiFilled`），用户改一下那栏点就消失（`markEdited`）—— 校对要有个落点；
- 名字只在还空着时补，用户自己敲进去的不被顶掉。

### 3.5 状态与并发保护

- **代次作废**（`draftSeq` / `visionSeq`）：等待中关向导、重开一轮、换一张图时，上一次的结果回来会对不上代次，整份丢弃 —— 否则会盖掉用户刚写的内容；
- 作废时要把 loading 一起松开（`cancelDraft` / `cancelVision`），否则按钮从此点不动；
- 一项都没解析出来时如实报错，不假装已经填好。

## 4. 第 2 步：Main view

模板： [CharacterPage.vue#L1428-L1513](../src/components/CharacterPage.vue#L1428-L1513)

- 左图右事：空态 / 生成中 / 已有图**共用同一个框**，点下去画面不跳；
- 这一屏回答两件最该说清的事：
  1. **它会拿哪张图当参考** —— `Generated from`：
     - 有参考图 ⇒ `Your reference image`（图生图）；
     - 没有 ⇒ `Text only — no reference image`（纯文生图）。
  2. **接下来该点哪里** —— 主按钮永远代表"接下来该做的那件事"：
     - 还没有正脸 ⇒ 主按钮是卡身里那个 `Generate main view`（`primary`）；
     - 有了正脸 ⇒ 主按钮交给卡脚的 `Next: other views`（卡身按钮降为普通描边，文案变 `Regenerate`）。

> 两个都涂黑会让"下一步做什么"变含糊，所以同一时刻主按钮只有一个。

- 生成中整格换成**停止入口**（暗幕 + CSS 绘制的停止方块 + 呼吸动画），与详情页设定图同一套。

## 5. 第 3 步：Other views

模板： [CharacterPage.vue#L1515-L1579](../src/components/CharacterPage.vue#L1515-L1579)

- 一列 2×2 的格子，**一律以主视图为参考图** —— 这就是"同一张脸"的保证；
  - 实际是**一排四格**（[.wz-grid](../src/components/CharacterPage.vue)）：四格统一用方框，
    竖幅的 `Full body` 在框里 `contain` 完整放下。照各自的真实比例铺，
    那一格会高出别人一截，四枚标签落不到同一条基线上 ——
    一排里"哪张不齐"会被读成"这张出了问题"。窄屏退回 2×2，同一条规矩；
- 这一屏是**两段**（`Main view` / `Other views`），各有自己的题头，
  与第 1 步那几段同一套（`.wz-group`）：主视图是基准，其余四张照它长。
  "一次补齐"挂在 `Other views` 的题头上 —— 说明与动作讲的是同一件事；
- 可**单张生成**，也可**一次补齐**（`generateAll`）；
- 一次补齐的按钮文案：`Generate N remaining`，四张齐了变 `All views ready` 并停下 —— 齐了还能点、点了没反应，看着像坏了；
- 说明里点出策略：一张一张来或一次补齐，**早期失败就停下**，而不是再烧四次调用。

### 五张设定图定义（[api.ts#L1402-L1466](../src/api.ts#L1402-L1466)）

顺序即生成顺序，也按"它补上了什么"排：

| kind | 标签 | 取景 | 补上了什么 |
| --- | --- | --- | --- |
| `front` | Front | square | 一张正脸，定"这个人是谁" |
| `detail` | Angles | square | 头部转面 2×2（左右正侧 + 上下 45° 俯仰），交代鼻梁、下颌线、耳位、发顶 |
| `full` | Full body | portrait | 全身，交代体型与服装轮廓 |
| `closeups` | Details | square | 细部特写 2×2（眼 / 皮肤与脸标 / 手 / 面料配件），交代材质与零件 |
| `body` | Body | square | 肢体 2×2（手 / 前臂 / 腿 / 脚），给"角色发一张自己身体的特写"当参考 |

> 注意：`kind` 是索引里的键，**可以改 label 与提示词，别改这个字符串** —— 改了库里已存的图会对不上。
> 唯一的例外是 2026-10-06 那次：`expression`（表情 2×2）**换成了 `body`**。换 key 而不是改语义，
> 是因为这次换的是**另一类内容**（脸 → 肢体），老图留着会被当成"肢体参考"发出去；那一格宁可为空。
> 与 `detail` 那次不同 —— 那次换的只是同一类内容里的另一种拍法（3/4 头像 → 转面头像）。
> 修饰词里**绝不能出现 "character reference sheet"**：它在图像模型那里是很强的排版概念，写进去模型真会画一张拼版而不是单人图。

## 6. 生成链路（App.vue）

实现： [genCharView](../src/App.vue#L1712-L1813)

### 6.1 参考图规则

- **正脸**：有 `sourceRef`（或老数据的 `ref`）就以它为参考图，没有就是纯文生图 —— 三种输入（上传 / 从作品提升 / 上一版正脸）走同一条流水线；
- **其余四张**：一律以正脸为参考图；正脸与底图一起送（底图补正面头像交代不了的发型轮廓、体态、服装轮廓）；
- 不认多图的模型（`caps.multiImage === 'no'`）**只送正脸** —— 宁可少一张，也不能为了多送一张把整个请求弄失败。

**参考图只管"这个人是谁"，不管"这一张怎么拍"**（2026-10-05 补。用户报："上传的参考图是侧面图，
则生成的正面图也是侧面的"）。

根因不是"正面"两个字没写 —— 那句一直在 —— 而是**参考图在 i2i 那条路上是最强的机位来源**：
图像编辑的默认行为就是保住输入的姿态，一句 `front-facing headshot` 拗不过它。
这正是 [角色配图构图与光影设计.md](角色配图构图与光影设计.md) **决定五** 里写的
"参考图同时是同一张脸的唯一保证，又是最强的机位与光线污染源"，而它当时只落进了
**提示词改写**那条路（`REF_NOTE`），没落到设定图上。

现在一起补（提示词由 `api.ts` 的 `characterViewPrompt` 一处拼，单测直接断言）：

| 补了什么 | 写在哪 |
| --- | --- |
| 正面拆成**可判定**的条件：两眼齐平且都可见、鼻尖朝向镜头、头不转不歪 | `front` 的 suffix |
| 三个否定：`not a profile` / `not a side view` / `not a three-quarter view` | 同上 |
| **把失败场景直接写进去**：`the face turned front-on even if the reference image shows the person from the side` | 同上 |
| `REF_IDENTITY_ONLY`：参考图只管脸/特征/头发/体型，**忽略它们的姿态、机位与光，不许跟着它们朝的方向抄** | 有参考图时追加在末尾。**写成复数**：正脸那格只送一张（底图），其余四格送两张（正脸 + 底图，见上表），单数那句到了那四格就指错对象 |

顺序是有意的：`characterViewPrompt` 拼的是"设定 → 取景 → 参考图那句"，
那句元指令垫在最末（与对话出图那条路的负面约束同一个排法），不挤掉"画什么"。

**它不适用于转面那一格**：`detail`（Angles）要的正是左右正侧与俯仰 ——
"别抄姿态"说的是"别抄**参考图**的姿态"，不是"别换方向"，单测把这两条钉在一起。

### 6.2 状态按「角色 + 视图」维度

这是几条硬约束的落点（曾出现过"生成 A 时切到 B，B 的格子也显示生成中"的问题）：

- `charViewBusy: Record<charId, CharacterViewKind[]>` —— 必须按角色分开；
- 中断手柄 `charViewControllers` 的键 = `` `${charId}:${kind}` ``；
- 同一张重复点无意义（第二次会盖掉第一次），**别的张在跑不影响这一张** —— 它们之间没有依赖。

### 6.3 依赖与守卫

| 情况 | 行为 |
| --- | --- |
| 正脸未生成 | 其余四格**上锁**（`isLocked`，`PhLockSimple` 图标套圆形底），而不是可点但会报错 —— 把顺序摆在明面上 |
| 正脸正在重跑 | 其余入口**停用**（`viewBlocked`）：那几张拿到的会是上一版正脸，"同一张脸"前提就破了。正脸自己不依赖任何视图 |
| 其余时候 | 几张可同时跑（它们之间没有依赖） |

### 6.4 中断与落库

- `stopCharView` 只 abort 对应那一张的手柄，别张不受影响；
- **只有成功写入那一刻才作数**，半路掐断不会留下坏图，旧图保留；
- 中断走 `notice` 显示 `Generation stopped.`，**不按报错处理**；
- 正脸生成成功后**写回 `c.ref`**（封面 / 头像 / 列表卡都读它），旧封面 Blob 的 object URL 释放；
- 重跑正脸后其余四张是照上一版正脸出的 ⇒ 提醒一句，但**不替用户删**（删不可逆，"要不要重跑"只有他知道）。

### 6.5 一次补齐

`genRemainingViews` **串行**跑：每张都以前一张为参考图，并行只会互相抢带宽；中途失败（多半是配置或配额）直接停下，免得连错四次。已经自己在跑的那张跳过。

### 6.6 按需加载

`loadCharViews(id)` 按角色缓存，已经取过就不再读 IndexedDB；同一 id 通过 `charViewsLoading` Map 去重（创作区选中角色的 watch 与角色页 @open 可能同时触发）。**启动时不碰这些图** —— 5 张 × N 个角色全读进来太重。

### 6.7 用角色开画时的注入

- `charSpecPrefix`（`characterFaceDesc`）拼在**用户提示词之后**：前段权重更高，把固定的长相顶在最前面会压掉"这一张要画什么"；
- `charRefSrcs` 并进参考图：**正面固定排最前**（前段权重更高，脸定在它上面），最多 `MAX_CHAR_REFS = 4` 张；上传的底图不在这里重复送（`c.ref` 里已是正脸）；
- 角色**不占表单的参考图槽**：表单上看到的始终是用户自己挑的那张，角色几张只在发请求时合进来。

## 7. 详情页（落地页）

详情页是角色的"家"：完整设定表、大图查看、用它开画。

- **hero**：头像用正脸（圆形容器裁的是一张脸）；名字 + 设定摘要；`heroMeta` 用量行（生成次数 → 创建时间 → 最后使用，没有的部分不占位）；标签（`N / 5 views`、`Main view · Front` 或 `No main view yet`）；右侧一次补齐 CTA。
- **Reference sheet 网格**：五格。
  - 空格点一下即生成；有图点开看大图；
  - 生成中整格换成停止入口；
  - 主视图（正面）带眼睛标 `PhEye`；其余空格在正脸未生成时上锁；
  - 生成进度显示在 panel 标题旁（视线必经位置）。
- **Made with this character**：该角色出过的图（来自历史，按 `characterId` 归拢），只摆最近 12 张，其余指路历史页。
- **Spec**：固定项按顺序排 + 可选 `Notes`（占满整行）。

### 大图查看器（`viewer`）

- 无底色设计，图片圆角 + 投影，翻页钮压在图两侧；遮罩固定深色（与主题无关）；
- 左右键翻页（到头绕回另一头，循环比禁用更好用），Esc 逐层退；
- 位置指示 `i / n`，只有一张时不显示（"1 / 1"是废话）；
- 动作只剩 **Regenerate**（主视图唯一=正面，不存在"设为主视图"）；正脸重跑期间其余视图的 Regenerate 停用；重跑时原地换成 **Stop**；
- **模态焦点管理**：打开时焦点收进来，关闭时归还到原格子；Tab 圈在浮层内（`trapTab`）。

## 8. 列表与卡片

- 角色海报卡：顶图全出血铺满，**封面 = 主视图**（生成正脸时写回 `ref`，所以列表读 `ref` 就够，不必为每张卡加载设定图）；3:4 比例，圆角、无边框、靠阴影浮起；
- 信息区毛玻璃 + 底部渐变暗幕托起白字（两者同一元素承载，避免边界不重合）；
- 名字与 **Create** 同排（`createWithCharacter`：套上角色并切回工作台）；
- 用量三格（生成次数 / 创建 / 最后使用）+ 竖向分隔；
- 特征胶囊最多三枚（`face → hair → eyes → outfit → marks`，跨场景不变的面貌特征排前面）；
- 管理动作（复制 / 导出 / 删除）收进右上角 `⋮` 菜单 —— 低频动作不该常驻，同一时刻只开一个。

## 9. 管理操作

| 操作 | 实现 | 要点 |
| --- | --- | --- |
| 新建 | `saveCharFromPage` → 角色页 `onSaved(id)` | `ref` 与 `sourceRef` **指向同一 Blob 但语义不同**，两个字段都写 |
| 编辑 | `saveCharFromPage`（带 id）→ `onUpdated(id)` | 名字 / 设定照单更新；**封面 `ref` 一律不碰**（换参考图不该顺手把脸换掉）；设定动了且已有设定图时提示重跑 |
| 复制 | [duplicateChar](../src/App.vue#L1507-L1538) | Blob 用 `reBlob`（`slice`）换实例 —— 两个角色共用一个 Blob 会共用 object URL，一边释放另一边图就裂了 |
| 导出 | [exportChar](../src/App.vue#L1542-L1554) | zip = `character.json` + `ref.*` + 五张视图；导出前先确保取过设定图（懒加载，不取包里会少五张） |
| 导入 | [importCharFile](../src/App.vue#L1563-L1604) | 文件里的 **id 一律换新**（撞上会让列表出现两条同 id，渲染和删除都错乱）；上限 64MB |
| 删除 | [deleteChar](../src/App.vue#L1456-L1492) | 立刻消失 + 几秒内可撤销，窗口结束才真正落盘并释放图；当前套用的角色会被 `detachCharacter` 摘掉 |

> 落盘顺序要求（复制 / 导入）：**先把图写进 IndexedDB，再 `saveCharacters`** —— 后者会按 key 归属清理，顺序反了会把刚写进去的图当成"已不在的角色名下"删掉。

## 10. 交互与无障碍要点

- **模态焦点陷阱**：向导与查看器都是模态，打开时焦点收进卡片本身（先让读屏念出这是什么），关闭时归还到触发它的按钮；同一时刻只会开一个；
- **Esc 逐层退**：先关大图 → 再关卡片菜单 → 再关向导 → 最后回列表；
- **代次作废在途请求**：起稿 / 识图都有 `seq`，关向导、换图、重开时旧结果整份丢弃；
- **notice 全局提示**：角色页的报错走 `notice`（`fail` 写的是首页那条 `.err`，在角色页不渲染等于没提示）；
- **所有状态按「角色 + 视图」隔离**，不同角色可同时生成设定图，各自独立显示状态与控制入口。

---

## 11. 一句话回顾

> 建角色是"填设定 → 出正脸 → 出其余四张"一条线，拆成三步一张卡；正脸是唯一主视图与整条流水线的锚，其余四张都照它生；设定管"这个人是谁"、参考图管"这个人长什么样"，两者分开存、分开用，才换来跨图的同一张脸。
