## 0. 一句话定位

**KImage 是一个「本地优先」的 AI 生图工作台**：前端是纯 Vue 3 SPA，后端只是一层自建 Node/Express 代理（把多家图像/文本/视觉/TTS 厂商统一成一套接口），**没有账号、没有云存储，全部数据留在浏览器**（IndexedDB + localStorage，API Key 也只存在本机）。

围绕「图」长出三条业务线：

| 线 | 解决什么 | 主要载体 |
| --- | --- | --- |
| 出图 | 一次提示词、多厂商/多模型、可对比、可复现 | [App.vue](../src/App.vue) 工作台 |
| 角色 | 跨图保持「同一张脸 + 同一套设定」 | [CharacterPage.vue](../src/components/CharacterPage.vue) |
| 对话 | 让角色「像它自己」地说话，并记得住 | [ChatPage.vue](../src/components/ChatPage.vue) |

外加两个工作面：**自由画布**（确定性几何编辑 + 局部 AI 编辑，[CanvasEditor.vue](../src/components/CanvasEditor.vue)）与**历史/提示词库/作品集**。

## 2. 数据与存储分层

一条贯穿全项目的分工原则：**轻目录进 localStorage，字节进 IndexedDB**。

### 2.1 localStorage（`kimage.*`，只存目录与当前值）

`kimage.apiConfigs`（接口配置列表）、`kimage.apiActive` / `apiActiveText` / `apiActiveChat` / `apiActiveVision` / `apiActiveTts`（五类用途各记一个「当前生效」）、`kimage.collections`（作品集目录）、`kimage.characters`（角色目录：设定/人格/嗓音）、`kimage.prompts`（提示词库元数据）、`kimage.theme`；旧键 `kimage.apiConfig` 保留迁移逻辑（[api.ts:340](../src/api.ts#L340)）。

注意「同一列表、五个当前值」：出图 / 改写 / 角色对话 / 识图 / 朗读五类配置用同一个 `ApiConfig[]`，但各自记 `activeId`。**对话那一个是例外中的例外**：`kimage.apiActiveChat` 为空（还没专配过）时，对话借改写那条用，界面上会写明 `from enhancing` —— 详见 [API配置管理设计.md](API配置管理设计.md) §5.4。

### 2.2 IndexedDB：`kimage.db` **v12**，9 张表（[lib/idb.ts](../src/lib/idb.ts)）

| 表 | 存什么 | 索引 |
| --- | --- | --- |
| `history` | 生成记录（含 Blob 图、缩略图、配方） | `createdAt` |
| `covers` | 提示词库卡片封面（Blob） | — |
| `chars` | 角色图：`{id}{SEP}{kind}` → 封面/底图/五张设定图 | — |
| `chat_messages` | 对话消息 | `charId`、`[charId, createdAt]` |
| `chat_images` | 聊天里用户附的图（v11 新增，与消息分开存） | — |
| `chat_summaries` | 每个角色一条长期记忆 | — |
| `tts_cache` | 合成音频片段（按文本+音色指纹） | `createdAt` |
| `voice_samples` | 克隆用的本地录音样本 | — |
| `chat_backdrops` | 对话全屏背景剧照（v12 新增，每个角色一张） | — |

连接的获取走 [lib/idb.ts](../src/lib/idb.ts) 里缓存的 `dbPromise`：`indexedDB.open` 是一次异步握手，连接可以复用，只在 `versionchange`（另一个标签页要升级）时关闭并清缓存。

版本号纪律写在文件里：**只能加不能减**，号比库里小会让 `open` 直接 `VersionError`，而调用方一律 catch 成「读不出来」——用户看到的就是「我的图全没了」。

### 2.3 存储治理

- `ensurePersisted()` 主动申请持久化配额，避免浏览器在压力下清掉。
- 写入即体检：`addHistoryRecord → pruneHistory()`，占用超 **80%** 水位就清掉最旧的 **30%**（`MIN_KEEP=20`、拿不到配额时 `HARD_LIMIT=500`）；**挂在作品集下的记录免清理**。
- 清理结果回传 `PruneResult`，主界面同步摘掉内存条目、`releaseEntryMedia` 释放 object URL、发一条全局提示。
- 图片载荷有两代形态：新记录是 `Blob`（在 JS 堆外），老记录是 data URL 字符串，读取侧两种都认（`imageSrc`/`thumbSrc`）。

### 3.3 关键机制（散落各处但全站一致）

- **四套独立 AbortController**：出图槽 `slotControllers`、设定图 `charViewControllers`、对话 `chatControllers`、改写 `enhanceController`；`AbortError` 一律记为 `stopped` 而不是失败。
- **生成槽 + 限流**：每张图 = 一个槽 = 一次请求，`runWithLimit` 限 **3 并发**；对比出图（Model Race）最多 **4 个模型**。
- **落盘约定**：IndexedDB 的结构化克隆不接受 Vue 响应式代理，写盘前一律 `toRaw`；缩略图与真实像素尺寸必须在记录进内存前补齐。
- **删除即撤销**：全站删除（历史/提示词/角色/配置/作品集/清空对话）都是「立刻生效 + 4.5s 撤销窗 + purge 才真删」，新删除先 purge 上一条。
- **防重入**：`chatLoading` / `charViewsLoading` / `chatSummarizing` / `savingChar` 四个闸门，外加 `chatSeq` 代次丢弃过期摘要结果。
- **能力表门控**：`getProvider(vendor, model)` / `inferVendor(baseUrl)` / `allowedSizes` 决定「发哪些扩展参数、尺寸手填还是枚举、走哪条编辑端点」；老配置没有 `vendor` 时按域名回填。
- **落盘/存储外的一切都派生**：角色用量 `charStats`、作品 `charWorks`、提示词短标题都不落盘，从历史记录现算 —— 老数据立刻就有数。

### 4.2 厂商适配

能力表在前端 [api.ts:132-185](../src/api.ts#L132)，服务端只按 `vendor + protocol` 分流：

| 厂商 | Base URL | 特点 |
| --- | --- | --- |
| openai | `api.openai.com/v1` | 唯一支持 quality/background；无 seed；多图；`/images/edits` |
| ark（豆包 Seedream） | `ark.cn-beijing.volces.com/api/v3` | 尺寸自由但**不认 `auto`**；单参考图；编辑走 generations |
| dashscope（通义万相） | `dashscope.aliyuncs.com/api/v1` | 同 ark 形状 |
| gemini | `generativelanguage.googleapis.com` | 原生协议；size 约分成宽高比；**没有 mask 字段**（edit 时把 mask 当第二张图并在文字里说明） |
| custom | 用户填 | 兜底；模型名含 gemini/banana 时自动按 Gemini 协议走 |

文本 / 识图另有两份预设（`TEXT_PROVIDERS` / `VISION_PROVIDERS`，含 DeepSeek、百炼 compatible-mode —— 百炼原生 `/api/v1` 打对话会 404）。

### 4.3 错误中文化（这块投入很大）

`CONNECT_HINTS` 把 `ENOTFOUND/ECONNREFUSED/ETIMEDOUT/ECONNRESET/EPIPE/UND_ERR_*` 与 TLS 错误码译成排查方向（含「配 `UPSTREAM_PROXY`」「加 `NODE_EXTRA_CA_CERTS`」这类具体动作）；`looksLikeHtml + htmlTitle` 认出「上游回了一整页 HTML」并抽 `<title>`，避免前端 `JSON.parse` 炸出 `Unexpected token '<'`；再有一层关键词翻译（`Images API is not supported` → 该走 native；`unknown parameter` → 多半是不支持 quality/background）。

### 4.4 安全与工程细节

- **无服务端密钥**：baseUrl/apiKey 全由前端随请求带；不挂 `cors` 是**故意的**（挂了等于让任意网站白用这个代理）。
- **SSRF 防护**：`assertSafeTarget + isBlockedAddress`，生产默认拒私网，DNS 解析后再校验。
- **限流**：内存滑窗 60s / 30 次（Serverless 下按实例生效，不是全局配额）。
- **超时/重试**：总超时 120s；流式与 TTS 改用「静默超时」（每收到一块就重置）；只有配置了代理时才做 [代理, 直连] 换跳，且**仅对连接层异常重试**；TTS 按字符计费，全程不重试。

## 5. 核心链路

### 5.1 出图（Studio 工作台）

`prompt` → 可选的提示词改写（`/api/enhance`，改写期间输入框只读 + 金色呼吸光晕）→ 参数行（模型+改写模型胶囊、角色胶囊、张数、尺寸、种子、画质、背景、参考图）→ 生成槽并发 3 → 落库（记录带 `configId/seed/ref/groupId/parentId/collectionId/characterId`）→ 底部历史图墙（12 格 + 骨架格）。

- **对比出图 Model Race**：多选模型（≤4）即对比，结果共用一个 `groupId`。
- **可复现的「整条配方」**：`reuseParamsOf` 把提示词、参数、种子、**当时那条配置 id**、参考图一起交回 —— 少了 configId，改一个变量重跑时用的其实是当前模型，对比就失真了。
- **创作链**：从某条记录重跑记 `parentId`（预览卡的 "Inspired by" 最多显示 3 层）；手动改提示词则断开链接。
- **作品集**：目录在 localStorage、归属挂在记录上；挂了归属的记录免于存储清理。

### 5.2 角色（Character）

一个角色 = **五张设定图 + 一段结构化设定 + 名字 + 一张底图**。核心设计：**参考图管「形状」，设定管「语义」**。

- **正脸是唯一的锚**：`front` 之外的四张（Angles / Full body / Details / Body）一律以正脸为参考图生成。
- **两个输入源分离**：`ref` = 封面/头像（正脸生成成功后就是正脸本身）；`sourceRef` = 第一步上传的底图（正脸生成会顶掉 `ref`，底图靠 `sourceRef` 保住，其余四张要拿它当第二张参考）。
- **字段结构化**：`CharacterFields` 前九项是「面貌特征」，会拼进每一张出图提示词（`characterFaceDesc`）；`outfit/marks` 只喂设定图。把性格分开存进 `CharacterPersona` —— 混进去等于让「它是什么人」污染「它长什么样」的像素级约束。
- **新建向导三步**：Basics（一句话 AI 起稿 `/api/enhance` mode:character；上传参考图自动识图 mode:vision；Name/Gender/结构化字段/人格四栏）→ Voice（browser/TTS，preset/describe/clone，可试听）→ Views（正脸先出，再四张）。
- **状态按「角色 + 视图」维度**：`charViewBusy: Record<charId, CharacterViewKind[]>`，A 在跑不影响 B；正脸重跑期间禁用其余入口（防止拿旧脸当参考）；逐张可独立停止。
- **导入导出**：一个 zip 带走设定 + 五张图 + **对话与长期记忆**（`ImportedChat`，记忆是主、消息是辅）；导入时换新 id 防止撞车；文件上限 64MB。

### 5.3 角色对话（Chat）

- **人格**：`persona` 六栏（language / traits / voice / address / boundaries / samples）在服务端拼成 system prompt，**刻意不喂** face/hair 等像素级字段；规则里写死「禁 markdown、1–3 句、不要每轮反问、可以不配合、禁元叙述」；温度 0.9、max_tokens 1500。其中 `samples`（说话样本）是 2026-10-08 加的，单独成段、带一句"抄语气不抄话题"的读法。
- **流式**：不是 SSE，而是把上游 `data:` 帧重新打包成 **NDJSON**（`{delta}` / `{done,finish,mood}` / `{error}`），并设 `X-Accel-Buffering: no`。前端按行切、留半行缓冲，`onDelta` 增量写回响应式消息。
- **三条不同的「没说完」**：用户按 Stop（`stopped`）、上游报错（`failure` 提示）、撞 `max_tokens`（服务端 `finish=length` → `truncated`，气泡下显示 "Cut off at the length limit"）。三者显示与后续行为都不同，`stopped` 的那条不给 Regenerate。
- **情绪**：模型在末行写 `[mood:word]`，服务端用 `CHAT_MOOD_RE` 剪掉并**单独下发**（正文里永远不含标签，前端不是"解析"而是原样收到），界面渲染成角色名旁的小药丸。
- **长期记忆**：窗口 20 条（服务端再拦 40 条），滑出窗口的消息压成一段简报存 `chat_summaries`；触发条件 `总数 − 窗口 − 已覆盖 ≥ 20`，单批上限 300 条；提示词要求「合并重写、绝不追加、<200 词、第三人称」；游标 `upToId/upToAt/covered` 让「该不该再压」不必全量重读。界面上记忆可见、可改、可忘。
- **朗读**：`browser`（哈希稳定挑音色 + 语速音高微调）与 `tts`（IndexedDB 缓存 → `/api/tts`）两档；TTS 失败**一定退回浏览器音色**并明确告知原因，而不是假装成功。

### 5.4 自由画布（Canvas）

- **状态模型**：图像 = 原始 `ImageBitmap` + 操作序列 `ops[]`（rotate / flip / crop / ai）；撤销、重做、跳步都是「弹栈后重放」，`replayAll` 一趟同时产出当前帧与步骤缩略图。**AI 步自带结果位图，重放不会二次调接口**（不重复花钱）。
- **工具**：pan / crop / lasso / eraser；AI 组＝套索、橡皮、去背景、换背景、照此再创作。
- **mask 语义**：遵循 OpenAI 的约定 —— **透明像素才是要改的地方**。去背景是整幅全透明；套索/橡皮是铺满不透明黑再 `destination-out` 挖空。
- **四种编辑模式**（`remove-bg / erase / regen / replace-bg`）走同一个 `/api/edit`，差异只在 mask 与是否有指令。
- **产物落成新记录**，不覆盖原图，并写 `parentId` 续上创作链；父组件用 `finishSave` 回执「存完了」。
- 细节：高分屏 `setTransform(dpr)`、`willReadFrequently` 探 alpha 决定 webp/png 还是 jpeg、载入超 3840px 先缩、rAF 合帧、`⌘Z/⇧Z/空格拖拽/V/C/L/E/Esc` 快捷键。

### 5.5 语音（TTS）

三档来源落到两个端点：`describe → /tts/create`（`seed-audio-1.0` + `text_prompt`，刻意不传 references、不带 Resource-Id）；`preset / clone → /tts/unidirectional`（`req_params.speaker` 是音色名或克隆 id）。鉴权头 `X-Api-Key / X-Api-Request-Id / X-Api-Resource-Id`，其中 Resource-Id 由「代际 + 商品」推断（preset ⇒ `seed-tts-*`，clone ⇒ `seed-icl-*`）。合成文本先 `tidyForSpeech` 规整（去 emoji/装饰、标点只在中文旁转全角），上限 600 字；写响应头推迟到第一帧音频，好让上游的拒绝能回一个正常的 502。

## 6. 设计系统

[style.css](../src/style.css) 顶部即 **Design System v1.0**（「克制 · Editorial · Image First」），[整体设计风格.md](整体设计风格.md) 是它的可复用版说明。

- **色彩**：暖白 `#FAFAF8` / 暖黑打底，一条完整灰度阶梯 + 四级文字灰；**全站只有一个强调色（墨色）**，深色主题下反相；彩色严格分工 —— 粉紫渐变只标「画布 AI 入口」这一身份，金色 `--ai-halo` 只报「机器正在跑」这一状态，红只用于危险。
- **排版**：正文系统字体栈；字标用自托管 Poppins + Pacifico（只引 latin）；**字阶按角色命名**（micro → 3xl），刻意保留 11/12/13/14/15/16 的密集档位；输入框 ≥16px 防 iOS 聚焦放大；全大写微标签单独一档字距 `--ls-eyebrow`。
- **组件语言**：卡片无边框 + 圆角 + 接触影、图片全出血；按钮只有主/次/图标三档，一屏一个实心；在途用呼吸光晕、破坏性操作给 4.5s 撤销条、结果提示挂全局层。
- **布局与响应式**：一级页面共用同一条最大栏宽（切换时左缘对齐）；三档语义断点 **860 / 720 / 640px**。
- **动效与无障碍**：一套主缓动 + 时长分层（入场慢、离场快），只动 `opacity/transform`；全站 `:focus-visible` 兜底、浮层焦点陷阱与归还、`prefers-reduced-motion` 下取消位移。

## 9. 观察与建议

**优先（工程健康）**

1. **尽快分批提交**：现在三条功能线（角色重做 / 画布 AI 编辑 / 角色对话）混在一个工作区里，任何一处回滚都会带走另外两处。
2. **拆大文件**：`App.vue` 5412 行承担了状态、落盘、编排、模板、样式五件事；建议按业务域抽 composable（`useConfigs` / `useGeneration` / `useCharacters` / `useChat` / `useHistory`），`App.vue` 只留装配与模板。`CharacterPage.vue`(5162) 至少可拆成 列表 / 详情 / 向导 / voice 面板；`CanvasEditor.vue`(4042) 可拆出「ops 重放引擎」与「canvas 绘制」。
3. **补最小测试**：不必全覆盖，优先三块纯逻辑 —— `api.ts` 的能力表与尺寸归一化、`lib/idb.ts` 的迁移与 prune、`server/index.js` 的错误翻译与请求归一化。这三处一旦错，表现都是「用户以为数据没了 / 图出不来」，最难靠手测发现。
4. **加 README + CI**：README 只需「怎么跑、需要什么、数据存在哪、密钥在哪」；CI 跑 `typecheck + build` 就够。

**其次（产品与体验）**

5. **无路由 = 无法深链**：页面状态在内存里，刷新回首页、也不能把「某个角色/某条记录」发给人。若要分享，至少把 `page` 与 `charId/entryId` 映射到 hash。
6. **密钥明文的取舍要写清楚**：本地优先意味着 Key 在 localStorage 里，部署给他人用时这层「信任边界」必须讲明（现在只有代码注释里有）。
7. **Serverless 下的限流形同虚设**：内存滑窗按实例生效，真要防滥用得换外部存储。
8. **文档归于一致**：把 §8 的三处不一致修掉，并把「已落地/暂缓/未实现」在一处列表里说清 —— 这四篇文档已经是这个项目最重要的资产，值得保持准确。
